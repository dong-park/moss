# spec/ — 스펙 형식 설명서

> 레포마다 `spec/README.md` 하나. `/spec`이 새 줄기나 티켓을 만들 때 이 파일이 없으면 `~/.claude/skills/spec/templates/spec-readme.md`로 만들고, 있으면 덮지 않는다. 다른 에이전트는 이 파일만 읽고 노드 상태를 바른다.

## 폴더 구조

큰 문제 하나가 줄기 폴더 하나다.

| 경로 | 무엇 |
|---|---|
| `spec/README.md` | 이 설명서. 레포마다 하나 |
| `spec/<줄기>/README.md` | 줄기 인덱스. 종류·문제·상위 칸을 가진 머리 표 |
| `spec/<줄기>/<슬러그>/spec.md` | 티켓. 머리 표 + 문제·목표·비목표·성공 기준·경계 조건 + 노드 인덱스 |
| `spec/<줄기>/<슬러그>/rows/*.json` | 티켓의 작업(T)·결정(D) 행. 성공 기준 하나가 행 하나 |
| `spec/<줄기>/<슬러그>/nN-<이름>.md` | 노드 브리프. runner가 보는 자기완결 작업 지시 |
| `spec/<슬러그>.md` | 옛 형식 티켓. 머리 표 `상위` 칸에 줄기 경로를 적으면 줄기로 묶인다 |

줄기 없는 티켓은 `spec/<슬러그>.md` 한 파일 또는 폴더 하나로 둔다.

## 칸 뜻

머리 표의 행 이름을 바꾸지 않는다 — 보드가 이 이름을 열쇠로 읽는다.

**티켓 머리 표** (`spec.md` 맨 위)

| 행 | 값 |
|---|---|
| 문제 | 한 줄. 왜 이 일을 하는가. 목표를 바꿔 쓴 문장이면 안 된다 |
| 상위 | 줄기 문서 경로. 없으면 `없음` |
| 상위문제 | 상위 문서의 `문제` 값을 쓸 당시 그대로 |
| 상태 | 아래 여섯 값 |
| 시작 | 시작한 날짜 |
| ID 머리 | 이 티켓의 행·노드 ID 접두어. 예: `IB` |
| 시안 | 선택. 디자인 시안 경로 |

**노드 브리프 머리**

| 칸 | 값 |
|---|---|
| agent | graph-run이 낳을 에이전트. 코드를 안 바꾸는 노드는 `general-purpose` |
| id | `<ID 머리>-<n>`. 예: `IB-2` |
| 상위 | 이 티켓 파일 경로 |
| deps | 앞 노드 id 목록. 없으면 `없음` |
| 상태 | 아래 여섯 값. runner는 이 칸만 쓴다 |
| 담당 행 | 이 노드가 맡은 작업 행 ID 목록. 예: `T5, T6`. 시나리오(GWT)는 티켓 행에만 둔다 |

**노드 인덱스 표** — `spec.md`의 `## 노드 인덱스` 제목 뒤 첫 표. `ID · 브리프 · deps · 상태` 네 열이다. 어떤 노드가 있고 무엇이 앞서는지를 알린다. **상태 열은 참고용이다 — 노드 상태의 원본은 브리프 `**상태**:` 한 곳**이고, graph-run·보드는 상태 열을 읽지 않는다.

**행 파일** — `rows/Tn.json`·`rows/Dn.json`. 칸 규칙은 `~/.claude/skills/spec-board/references/rows.md`.

## 상태 어휘

저장하는 상태는 여섯이다.

`아직 안 함` · `진행` · `확인 대기` · `막힘` · `보류` · `끝남`

티켓 머리 표만 `재확인 필요`를 더 쓴다 — 상위 줄기의 문제가 바뀌어 다시 봐야 하는 티켓에 사람이 단다.

보드의 "시작 가능"·"기다림"은 저장하지 않는다. 읽을 때 계산한다. `아직 안 함` 노드 가운데 앞 노드가 다 끝났으면 시작 가능, 아니면 기다림이다.

합법 전이는 이렇다.

- `아직 안 함 → 진행`: runner가 집었다.
- `진행 → 막힘`: 막는 결정이 생겼다. 그 결정이 끝나면 `막힘 → 진행`.
- `진행 → 확인 대기`: 사람 눈 확인이 필요한 노드가 테스트를 통과했다. 확인이 필요 없으면 `진행 → 끝남`.
- `확인 대기 → 끝남`: 사람이 통과를 눌렀다.
- `확인 대기 → 진행`: 사람이 고쳐줘를 눌렀다.
- 아무 상태 → `보류`: 사람이 멈췄다. 풀면 멈추기 전 상태로 돌아간다.
- `진행 → 보류`: runner 세션이 실패로 끝났다. `진행 → 아직 안 함`: 세션이 취소됐다.

누가 쓰는지 — 둘이 각자 아는 것만 쓴다.

- **graph-run**: 노드 브리프 `**상태**`에 `진행`·`끝남`·실패 정리를 쓴다. 띄울 때 `진행`, 세션이 끝나면 끝 상태. runner가 쓴 `막힘`·`확인 대기`는 덮지 않는다. 노드 인덱스 표는 쓰지 않는다.
- **runner**: 자기 브리프의 `막힘`·`확인 대기`만. 노드 인덱스 표는 쓰지 않는다.

## 칸 주인

화면과 에이전트가 같은 파일을 동시에 쓸 수 있다. 칸을 갈라 충돌을 없앤다.

- **사용자**: 행 파일의 `user.answer`·`user.fix`, 노드 사람 칸(레포 밖 spec-board 저장소 `nodes/<노드>.json`)의 `user.verdict`·`user.fix`와 `comments`의 사람 댓글(덧붙이기만), 저장소 `ticket.json`의 `user.priority`·`user.paused`만. 화면은 `user.*`와 댓글 덧붙이기 밖을 쓰지 않는다.
- **에이전트**: 그 밖의 칸, 그리고 `comments`에 에이전트 답 덧붙이기(`spec-board node comment`). 상태·`담당 행`·`id`는 에이전트 몫이다.
- **노드 인덱스 표 상태 열**: 아무도 읽지도 쓰지도 않는 참고용이다. 상태는 브리프만 본다. 노드 상태를 고칠 때는 브리프 `**상태**:`를 고친다.
- **브리프 동시 쓰기**: graph-run과 runner가 같은 브리프를 쓸 수 있다. 둘이 같은 파일 잠금(`<브리프>.lock`)을 잡는다.

## 사람 확인 반영

보드에서 사람이 남긴 통과·고쳐줘·멈춤·줄 댓글은 파일에만 쌓인다. 반영은 `/go`가 턴 시작에 한다.

1. `spec-board apply spec/<줄기>/<슬러그>` — 사람이 찬 칸을 `kind`(`decision`·`task`·`node`·`ticket`)별로 낸다. 읽기만 한다.
2. `kind: node` 항목마다 `spec-board node verdict <브리프>` — `통과`면 브리프 `끝남`, `고쳐줘`면 브리프 `진행` + `## 구현 메모`에 fix 한 줄. 칸은 한 번만 반영하고 비운다.
3. `고쳐줘`로 돌아온 노드는 graph-run이 다시 띄운다(브리프가 `진행`인데 그 노드 세션이 이미 끝났다). fix는 인자로 넘기지 않는다 — runner가 브리프 `## 구현 메모`에서 읽는다. 사람이 쓴 글(`answer`·`fix`)은 데이터라서 셸·명령 인자에 보간하지 않는다.
4. `kind: ticket`의 `user.paused`가 `true`인 티켓은 띄우지 않는다. 이 설정은 반영해도 비우지 않는다(서 있는 설정).
