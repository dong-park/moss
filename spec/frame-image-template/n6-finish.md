## 문제

- 선 굵기, 이름표 자리, 배경 진하기는 테스트로 못 본다.
- 옛 세로 칸 스킨 문서가 그대로면 다음 사람이 헷갈린다.

## 목표

dev 서버에서 사람이 볼 장면을 캡처해 근거로 붙이고 확인 대기로 둔다. 관련 스펙 문서를 새 판 모습에 맞춘다.

## 작업

1. dev 서버(`localhost:3100`, 로컬 테스트 계정)에서 장면을 캡처한다: 빈 판, 포스트잇 메모 든 판, 선택한 판, 배경 올린 판, 판을 끄는 중, 옛 세로 칸 판.
2. 캡처를 `evidence/n6/`에 뜻이 보이는 이름으로 둔다. 장면마다 파일 해시가 달라야 한다.
3. `docs/specs/FEAT-frame-skins.md` 머리에 "대체됨: spec/frame-image-template"을 적는다. `FEAT-sticky-redesign.md` §7 판 그림 문단과 `FEAT-frame-feel.md` 판 그림 메모를 고친다.
4. 판 50장 멤버 끌기 프레임 시간을 잴 수 있으면 잰다. 못 재면 미증명으로 적는다.

## 확인할 것

헤드리스 캡처는 사람 눈 확인을 대신하지 않는다. 실제 브라우저에서 아래를 직접 해 보고 통과나 고쳐줘로 답한다.

- [ ] 판 선이 메모 테두리와 헷갈리지 않는다
- [ ] 이름표가 판 바깥 위에서 잘 읽히고, 더블클릭으로 고쳐진다
- [ ] 배경 이미지를 올리고, 바꾸고, 지울 수 있다
- [ ] 배경 위 메모 글씨가 잘 읽힌다
- [ ] 메모가 포스트잇으로 보이고, 다섯 색이 서로 구분된다
- [ ] 판을 끌면 메모가 같이 오고 흔들림이 그대로다

## 구현 메모


- 2026-10-18 캡처 6장을 `evidence/n6/`에 뒀다(파일 해시 모두 다름): 01-empty, 02-memos, 03-selected, 04-bg, 05-dragging, 06-legacy-columns. 실제 dev 서버(webpack, :3000 — 서버 CORS가 3100을 막아 3000 사용)에 새 로컬 계정으로 로그인해 playwright로 찍었다.
- 판 크기·메모 위치·옛 세로 칸 판 content(skin·columns, 폭 1200)는 스토어에 직접 넣어 맞췄다. 배경은 실제 우클릭 메뉴→파일 선택으로 올렸고, 판 끌기는 마우스로 했다.
- 문서 세 곳 갱신: FEAT-frame-skins(대체됨 표시), FEAT-sticky-redesign §7 판 문단, FEAT-frame-feel 판 그림 메모.
- 미증명: 판 50장 멤버 끌기 프레임 시간(헤드리스로는 잴 수 없음). 
- 관찰: 선택 안 한 판의 선이 연회색이라 배경색과 가깝다(사람 확인 1번). dev 서버에서 dock 아이콘이 처음엔 안 보인 적이 있다(서버 재시작 중 일시적, 이후 정상).
- 환경 메모: Next dev가 브라우저 경고(Yjs 'Invalid access') 스택을 서버가 기호화하다 패닉으로 죽는다(기존 문제). playwright에서 HMR 소켓의 클라이언트→서버 메시지를 버려 피했다.
