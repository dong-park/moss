## 문제

단위 테스트는 힌트 위치, 유리벽 위의 첫 획, 두 번 누르기 손맛을 보여 주지 못한다.

## 목표

새 브라우저 프로필에서 첫 실행부터 새로고침까지 시안 03-a·03-b와 같은 화면이 나오는지 확인하고 결과를 기록한다.

## 선행 (다른 티켓)

- local-promise 로그인 게이트 철거 — 없으면 로그인 뒤부터 확인하고 T1의 "로그인 화면 없음"은 보류로 적는다.
- glass-surface 유리 배경 — 없으면 바탕 재질은 판정하지 않는다.
- wall-marker 마카 트레이·벽 획 저장 — 없으면 T3은 보류로 적는다.

## 작업

1. dev 서버를 띄우거나 떠 있는 것을 쓴다. 저장소를 비운 새 프로필로 연다.
2. 아래 순서로 보고 단계마다 스크린샷을 남긴다. 결과는 행마다 통과·실패·보류 셋 중 하나다.
   - T1·T2: 첫 화면에 고르기 창 없음, 빈 벽, 아래 가운데 힌트 한 줄. 03-first-a와 대조.
   - T3: 마카로 "요즘 자꾸 떠오르는 거"를 쓰고 밑줄 → 힌트 사라짐, 묻는 창 없음.
   - T4: 빈 곳 두 번 누름 → 그 자리 노랑 포스트잇, 바로 입력, "회사 옮길까?" 입력. 03-first-b와 대조.
   - T5: 새로고침 → 같은 벽, 같은 자리, 힌트 없음.
   - T6: 새 포스트잇을 빈 채로 두고 Esc → 남아 있음, 새로고침 뒤에도 남음.
3. 결과 표와 스크린샷 경로를 이 파일 구현 메모에 쓴다.

### T4 실패 — 첫 포스트잇이 누른 자리가 아니라 화면 가운데로 붙는다

재현 순서:
1. 빈 프로필로 `/`를 연다(힌트가 보이는 빈 벽).
2. 마카 없이 벽 빈 곳 (300, 220)을 두 번 누른다 — (520, 400), 힌트 글자 (600, 660)에서도 같다.
3. 포스트잇이 누른 점이 아니라 화면 가운데(좌상단 ≈ (477, 257), 크기 ≈ 245)에 붙는다.
4. 같은 벽에서 한 번 더 (900, 200)을 두 번 누르면 이번에는 (899, 199)에 정확히 붙는다 — 첫 장만 튄다.

원인(코드로 확인):
- `Canvas.tsx`의 `onDoubleClick`은 맞다. 카드는 누른 월드 좌표 (300, 220)에 만들어진다(DOM `left:300px; top:220px`).
- 그런데 같은 파일의 "새로고침 직후 1회 fit" 효과(`didFitRef`, `if (cards.length === 0) return; … fitToCards()`)가 빈 벽에서는 로드 때 돌지 못하고, **첫 카드가 생기는 순간** 돌아 뷰포트를 그 카드 가운데로 옮긴다. 월드 레이어가 `translate(0,0)` → `translate(180px,40px)`로 바뀐다.
- 그래서 사용자 눈에는 포스트잇이 누른 자리가 아니라 화면 가운데에 나타난다. 누른 점이 화면 가운데에서 멀수록 어긋남이 크다(힌트 글자 (600, 660)를 누르면 좌상단이 (477, 257)로 가서 약 400px 위로 튄다).
- n4 단위 테스트는 `addCardAt`에 들어가는 좌표만 보고 뷰포트를 보지 않아 이를 못 잡았다(n4 리포트 「실경로 갭」에 이 갭이 적혀 있었다).

손볼 곳 후보(이 노드는 검증 노드라 고치지 않았다): `Canvas.tsx` 최초 fit 효과가 "로드로 들어온 카드"에만 돌게 하거나, 사용자가 이 세션에서 만든 카드(dblclick·Dock)가 생길 때 `canvasHasFitted`를 먼저 세운다.

### 그 밖의 관찰

- 로드 직후 힌트 깜빡임(n3이 n6 확인으로 넘긴 항목): 카드 3장이 있는 벽을 3번 새로고침하며 10ms 간격으로 샘플링했고 힌트가 한 번도 뜨지 않았다. 문제 없음.
- 빈 포스트잇의 색조가 id 해시로 6단계(레몬~꿀) 중 하나라, 꿀색(`#ffcf6e`)은 주황에 가깝게 보인다(`fw6-09`의 오른쪽 위). FEAT-memo-variety의 기존 설계이고 "노랑 계열"이다.
- 포스트잇 모양(제목 띠가 있는 종이, 시안의 손글씨 느낌 없음)은 sticky-handfeel·glass-surface 몫이라 판정하지 않았다.
- DOM 안에는 화면 밖 시그널스 서랍의 "조금 더 머무르면 패턴이 보일 거예요"(`signals` 키)가 있다. 화면에는 보이지 않는다.
- Next dev 인디케이터("N" 원)는 dev 서버 전용이다.

### 게이트 갭

- 헤드리스 Chrome + CDP 합성 입력이라 실제 마우스 두 번 누르기의 손맛·태블릿 두 번 탭 확대 방지·포스트잇 textarea의 실포커스 느낌은 사람 눈 확인이 필요하다. 합성 입력은 DOM 이벤트·포커스·저장 경로까지는 실제와 같다.
- 시크릿 모드·저장소 차단(T9 실제 브라우저 오류)은 이 노드 담당 행(T1~T6)이 아니라 보지 않았다.
