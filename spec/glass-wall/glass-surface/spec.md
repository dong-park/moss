## 문제 — 지금 캔버스는 회색 앱 바탕이라 벽처럼 느껴지지 않는다

지금 보드 바탕은 밋밋한 회색 면 하나다. 그 위에 포스트잇을 붙이고 마카로 써도, 사용자는 벽이 아니라 앱 화면을 보고 있다고 느낀다. 줄기 전체가 "벽에 손으로 쓰고 붙인다"는 감각에 기대므로, 바탕이 벽이 아니면 다른 티켓의 손맛도 살지 않는다.

## 목표 — 캔버스 바탕 전체가 뒤가 살짝 비치는 유리벽이 된다

보드를 열면 바탕 전체가 유리벽이다. 유리 뒤로 방이 흐릿하게 비치고, 사선 반사광과 깊이감이 있다. 재질은 유리·화이트보드·코르크 셋 중에서 고를 수 있고, 고르지 않으면 유리다. 메모판은 벽에 걸린 판처럼 보이고, 메모판 재질은 벽과 따로 고른다.

## 비목표 — 마카 트레이, 배지 문구, 대규모 성능은 다른 티켓까지만

- 마카 트레이의 모양과 동작은 wall-marker 몫이다. 이 스펙은 트레이가 놓일 아래 중앙 자리가 바탕과 겹쳐도 읽힌다는 것까지만 본다.
- 오른쪽 위 저장 위치 배지의 문구와 동작은 local-promise 몫이다. 이 스펙은 배지가 앉을 자리와 그 자리의 바탕 처리까지만 만든다.
- 포스트잇 수천 장에서의 팬·줌 성능은 wall-scale 몫이다. 이 스펙은 바탕 하나가 더하는 비용만 잰다.
- 메모판 스킨의 칸 그림은 FEAT-frame-skins 몫이다. 이 스펙은 메모판의 테두리·그림자·핀과 메모판 재질까지 다룬다. 칸 선은 메모판 재질 위에 그대로 그린다.
- 스티커, 테마, 장식, 사용자 사진 배경은 만들지 않는다. 재질은 벽과 메모판 모두 같은 세 개로 끝난다.
- 재질마다 마카 색을 바꾸지 않는다. 코르크 위 빨강·초록 마카가 옅게 보이는 것은 받아들인 제약이다.
- 휴대폰 화면 배치는 phone-to-wall 몫이다. 바탕 그림 자체는 휴대폰에서도 같다.

## 성공 기준 — 행 파일이 곧 성공 기준이다

행 파일이 곧 성공 기준이다.

## 경계 조건 — 저장값이 틀려도 유리로 열리고, 블러를 못 쓰면 불투명 유리로 바뀐다

- 재질 값이 없는 예전 보드는 유리로 연다.
- 재질 값이 모르는 이름이거나 깨져 있으면 유리로 연다. 오류 창은 띄우지 않는다.
- 메모판 재질 값이 없거나 깨져 있으면 코르크로 그린다. 예전 메모판도 코르크로 보인다.
- 브라우저가 블러를 못 그리거나 사용자가 투명도 줄이기를 켰으면, 뒤 방 대신 불투명한 젖빛 유리 면을 그린다.
- 재질을 바꾸는 중에 포스트잇을 끌고 있어도 끌기는 끊기지 않는다. 바탕만 바뀐다.
- 공유 보드에서 재질을 바꿀 때의 범위는 D2가 정한다.
- 아주 큰 화면이나 아주 작은 화면에서도 반사광은 화면 비율을 따라 늘어날 뿐 잘리지 않는다.

## 상태 모델 — 보드와 메모판이 각자 재질 하나, 세 값만 합법이다

보드 하나는 언제나 벽 재질 하나를 갖는다. 메모판 하나도 언제나 메모판 재질 하나를 갖는다. 합법 값은 둘 다 유리, 화이트보드, 코르크다. 셋 사이의 전이는 모두 허용되고, 전이는 그 바탕 그림만 바꾼다.

불가능한 조합은 넷이다. 재질이 둘인 보드나 메모판은 없다. 벽 재질을 바꿨는데 메모판 재질이 따라 바뀐 상태는 없다. 재질이 바뀌었는데 포스트잇이나 마카 획의 좌표가 바뀐 상태는 없다. 재질이 비어 있는데 유리가 아닌 바탕이 그려진 상태도 없다.

## 기술 결정 — 바탕은 미리 흐린 고정 그림이고, 캔버스 위에 실시간 블러를 걸지 않는다

- 뒤 방은 처음부터 흐린 그라데이션 그림으로 그린다. 카드 아래에 실시간 블러를 걸면 팬할 때마다 다시 계산해서 느려진다. 자세한 선택은 D5다.
- 재질은 바탕 레이어 하나만 갈아 끼운다. 카드, 획, 메모판 레이어는 재질을 모른다. 그래야 재질을 더할 때 다른 티켓을 건드리지 않는다.
- 재질 이름은 레지스트리 하나에 모은다. 메모판 스킨 레지스트리와 같은 모양으로 둔다.

## 확인 안 된 것 — 메모판 재질의 기본값과 고르는 자리는 시안에서 추정했다

메모판 재질을 따로 고른다는 답은 받았다. 기본을 코르크로 둔 것은 시안 01의 메모판 모습을 따른 것이다. 고르는 자리를 판 우클릭 메뉴로 둔 것은 메모판 스킨과 같은 자리라서다. 둘 다 사용자가 확인하지 않았다.

## 공통 완료 기준 — 테스트·타입·i18n이 통과하고, 실경로를 탄다

1. `cd web && bunx tsc --noEmit` 통과.
2. 노드가 건드린 테스트 파일 통과. 메모리에 적힌 플래키 테스트 2종이 실패하면 단독 재실행으로 판정하고 구현 메모에 남긴다.
3. 문구를 더한 노드는 `cd web && bun run check:i18n` 통과.
4. 새 로직마다 테스트 최소 1개, 커밋은 Conventional Commits.
5. 실경로 검증. stub이나 직접 주입으로만 green이면 갭을 노드 브리프 구현 메모에 적는다.
6. 마카 트레이, 배지 문구, 수천 장 성능, 포스트잇 손맛은 만들지 않는다. 각각 wall-marker, local-promise, wall-scale, sticky-handfeel 몫이다.

## DAG — 데이터 하나에서 바탕, 그다음 고르는 자리 둘로 갈라진다

```
n1-material-model ──► n3-wall-surface ──┬──► n4-material-picker ──┐
        │                               └──► n5-hung-frame ───────┤
        ├──────────────────────────────────► n4 (setter)          ├──► n6-browser-check
        └──────────────────────────────────► n5 (setter)          │
n2-hand-font ─────────────────────────────────────────────────────┘
```
