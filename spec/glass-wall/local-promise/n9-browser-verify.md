## 문제

단위 테스트는 "서버로 아무것도 안 나간다"를 증명하지 못한다.

배지 약속은 실제 브라우저의 네트워크 기록과 서버 DB로만 확인된다. 로그인, 업로드 실패, 다른 기기 로그인도 실제 스택에서만 재현된다.

## 목표

로컬 스택과 실브라우저에서 T1부터 T15까지 각 행의 Then이 그대로 보인다. 각 행의 판정과 근거를 이 파일 구현 메모에 남긴다.

## 준비

- 로컬 스택: 레포 루트에서 `docker compose up -d`. postgres·Ktor 서버·동기화 서버가 뜬다.
- 웹: `cd web && bun run dev`. 3000번이 이미 moss면 재사용한다.
- 브라우저: Playwright 컨텍스트 여러 개. Google 실로그인 대신 서명 JWT 주입을 쓸 수 있다. 이 방법은 FEAT-collab-auth 구현 메모에 있다. 단 T8 로그인 창 닫기는 로그인 함수를 실패시키는 방식으로 재현한다.
- 네트워크 기록: 모든 요청을 저장하고 API 출처와 동기화 출처 요청 수를 센다. 모든 요청 주소와 본문에서 포스트잇 글을 찾는다.

## 확인할 행

| 행 | 판정 방법 |
|---|---|
| T1 | 새 컨텍스트로 `/`를 열면 로그인 화면 없이 벽과 "🔒 이 기기에만"이 보인다. 쓰고 새로고침해도 남는다 |
| T2 | 로그인 없이 마카 획 5개, 포스트잇 3장, 옮기기, 지우기, 새로고침. API·sync 출처 요청 0건, 모든 요청에서 포스트잇 글 0건 |
| T3 | 혼자 쓰는 벽 A와 공유한 벽 B 사이를 오가며 배지 문구를 본다. 다른 탭 배지도 바뀌는지 본다 |
| T4 | 시트 제목·본문·버튼 문구가 시안 06과 같다 |
| T5 | 취소와 Esc. Google 창 없음, 서버 요청 0건 |
| T6 | 로그인 없이 마카 획 4개와 포스트잇 5장을 쓰고 공유. 초대 링크로 들어온 둘째 컨텍스트에 같은 자리로 보인다 |
| T7 | 벽 3개 중 하나만 공유. 다른 컨텍스트로 같은 계정 로그인 시 그 벽 하나만 보인다. 서버 DB에서 그 계정 보드 행 수가 1이고 파일함만 더해진다 |
| T8 | 로그인 실패 시 실패 문구, 배지 그대로, 서버 DB에 그 벽 행 없음 |
| T9 | 업로드 도중 오프라인 전환. 실패 문구와 "다시 시도", 배지 그대로. 다시 시도해 성공하면 "☁ 공유 중" |
| T10 | 로그인 상태를 미리 저장한 컨텍스트로 열면 안내 없이 마지막 벽이 열리고 배지가 벽마다 맞다 |
| T11 | 로그인한 상태에서 같은 시트에 "공유"와 "취소". Google 창 없이 공유 중 |
| T12 | 로그아웃 뒤 같은 벽이 보이고 계속 쓸 수 있다. 공유 벽 배지는 "☁ 공유 중 · 로그인하면 맞춰요" |
| T13 | 공유 해제 뒤 배지가 돌아오고, 이후 고쳐도 API·sync 요청 0건 |
| T14 | 로그인 안 한 컨텍스트로 초대 링크. 초대 카드와 Google 버튼, 로그인하면 공유 벽. 그 컨텍스트의 혼자 쓰던 벽은 서버 DB에 없다 |
| T15 | 첫 벽에서 공유. 덧붙임 한 줄, 새 벽이 공유 중으로 열림, 첫 벽은 비고 "🔒 이 기기에만" |

## 작업

1. 위 준비를 하고 표 순서대로 확인한다.
2. 행마다 통과·실패·확인 못 함 중 하나와 근거 한 줄을 구현 메모에 적는다. 근거는 스크린샷 경로, 요청 수, DB 쿼리 결과 중 하나다.
3. 실패한 행은 고치지 않는다. 재현 순서와 함께 적고 상태를 `parked`로 둔다.
4. 손글씨 폰트가 외부 출처에서 오는지 네트워크 기록에서 본다. 오면 glass-surface 몫으로 적는다.
5. 끝나면 QA로 넣은 서버 DB 행과 로컬 데이터를 지운다.
