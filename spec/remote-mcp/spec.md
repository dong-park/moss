# moss 원격 MCP

| 항목 | 값 |
|---|---|
| 문제 | 서비스 사용자의 AI 에이전트가 moss 보드에 붙어 메모를 읽고 쓸 통로가 없다 |
| 상위 | 없음 |
| 상위문제 | 없음 |
| 상태 | 아직 안 함 |
| 시작 | 2026-10-18 |
| ID 머리 | RM |

## 문제 — 지금 MCP는 개발자 PC 탭을 거쳐서만 동작해 서비스 사용자에게 줄 수 없다
- 사용자는 Claude·ChatGPT·Cursor 같은 클라이언트에서 자기 보드를 다루고 싶다.
- 기존 mcp/ 는 열린 브라우저 탭에 로컬 소켓으로 붙고 개발 빌드에서만 켜진다.
- 개인 보드는 브라우저 안에만 있어 서버 쪽 도구가 읽을 수 없다.

## 목표 — 사용자가 커넥터 하나로 자기 보드를 에이전트에게 맡긴다
서비스가 원격 MCP 엔드포인트를 열고, 사용자는 커넥터를 추가해 자기 계정으로 로그인한다. 에이전트는 로그인한 사용자 본인으로 행동하며 권한은 보드 멤버십을 따른다. 이를 위해 로그인한 사용자의 보드를 모두 서버에 저장한다.

## 비목표
- AI 전용 계정이나 AI 커서는 만들지 않는다. 협업 기능과의 경계는 사용자 본인 행동까지다.
- 기존 mcp/ 의 dev_*·ai_* 도구를 원격으로 옮기지 않는다.
- 로그인하지 않은 사용자의 MCP는 지원하지 않는다.
- 다중 sync 인스턴스 확장(Redis)은 이번에 하지 않는다.

## 성공 기준 — 행 파일이 곧 성공 기준이다
rows/T1~T11이 기준이다. 결정은 rows/D1~D8이고 2026-10-18 모두 답을 받았다. D4는 B(범위 없이 읽기쓰기 하나)라 T10은 보류했다. 나머지는 추천값이다.

## 경계 조건
- 보드 한 장의 크기는 sync의 기존 한도를 따른다. 초과하면 변경이 거절된다.
- 에이전트와 사용자가 같은 메모를 동시에 고치면 Yjs 병합 규칙을 따른다.
- 사용자가 보드 멤버에서 빠지면 다음 도구 호출부터 그 보드는 거절된다.
- 접근 토큰이 만료되면 갱신 토큰으로 갱신하고 실패하면 다시 승인을 받는다.
- 에이전트의 요청당 변경 수와 분당 호출 수는 상한이 있다.

## 기술 결정
- **MCP 엔드포인트는 sync 프로세스 안에 둔다.** Hocuspocus openDirectConnection으로 문서를 고치면 브라우저에 즉시 반영되고 저장 경로와 크기 제한이 같다.
- **문서 모델은 공용 패키지로 분리한다.** 필드 목록이 두 벌이면 필드 누락 사고가 되풀이된다.
- **인가 서버는 Ktor에 둔다.** 계정과 멤버십이 이미 Ktor에 있다. MCP 토큰은 웹 세션과 별개다.
- 도구는 10개 안팎: 보드 목록, 보드 읽기, 검색, 메모 생성·수정·삭제, 연결 생성·삭제, 첨부 업로드.
