# Spec: 메모 색 고르기
Started: 2026-10-02

## 목표
메모지마다 색을 하나 골라 붙일 수 있게 한다.
색은 5개만 두고, 모두 옅고 차분한 톤으로 맞춘다.
고르는 곳은 메모 우클릭 메뉴 하나다.

## 비목표
- 새 카드 종류를 만들지 않는다. 체크리스트 카드와 링크 카드는 이번에 안 한다.
- 도크에 색 도구를 넣지 않는다.
- 글상자, 사진, 판, 함 카드의 색은 바꾸지 않는다. 메모지만 대상이다.
- 사용자가 직접 색을 지정하는 색상환은 없다. 정해 둔 5개 중에서만 고른다.
- 색으로 거르거나 정렬하는 기능은 안 한다.
- 색 바꾸기 전용 되돌리기는 만들지 않는다. 지금 카드 속성 변경에는 되돌리기가 없다.

## 성공 기준
1. 메모 우클릭 메뉴에 "색" 하위 메뉴가 있고, 항목이 정확히 5개다.
2. 각 항목에는 색 점 하나와 이름이 붙는다. 지금 색 항목에는 체크 표시가 붙는다.
3. 하나를 고르면 그 메모의 색이 다음 프레임 안에 바뀐다.
4. 바뀐 뒤에도 종이 결 무늬가 그대로 보인다. 바뀌는 건 색조 층 하나뿐이다.
5. 여러 장을 선택한 상태에서 그중 한 장을 우클릭해 고르면, 선택된 메모 전부가 같은 색이 된다.
6. 선택 안에 메모가 아닌 카드가 섞여 있으면 그 카드는 건드리지 않는다.
7. 새로고침해도 고른 색이 남는다.
8. 공유 보드에서 한 사람이 바꾸면 다른 사람 화면에도 같은 색이 보인다.
9. "기본"을 고르면 저장된 색이 지워지고, 지금처럼 id 해시로 정해지는 노랑 6단계로 돌아간다.
10. 색을 한 번도 안 고른 기존 메모는 지금과 똑같이 보인다. 화면 차이 0픽셀이다.
11. 표 보기의 색 점이 고른 색을 그대로 보여 준다.
12. 펜 모드나 편집 중에는 메뉴가 안 열린다. 지금 메뉴 규칙과 같다.
13. 메뉴 문구는 전부 ko.json 키로 들어간다. 하드코딩 문자열은 0개다.

## 경계 조건
- 저장된 색 값이 5개 목록에 없으면 기본 노랑으로 그린다. 옛 데이터나 다른 클라이언트가 이상한 값을 넣어도 화면이 깨지지 않는다.
- 같은 메모를 두 사람이 동시에 바꾸면 나중에 도착한 값이 이긴다. 기존 동기화 규칙을 그대로 따른다.
- 여러 장을 바꿀 때는 한 번의 상태 갱신으로 처리한다. 200장을 골라도 저장 요청이 카드마다 따로 나가지 않게 한다.
- 이미 그 색인 메모를 다시 고르면 아무것도 쓰지 않는다.
- 읽기 전용으로 공유받은 보드에서는 색 메뉴를 보여 주지 않는다.
- 메모 펼침 창은 지금 색조를 쓰지 않는다. 이번에도 손대지 않는다.

## 기술 결정
- 기존 `color` 칸을 쓴다. DB, 동기화 키, 내보내기에 이미 길이 나 있어 새 칸이 필요 없다.
- 저장 값은 hex가 아니라 팔레트 이름이다. 나중에 색 톤을 다듬어도 저장된 데이터를 고칠 필요가 없다.
- 기본 노랑은 저장하지 않는다. 칸이 비어 있으면 기본이다. 기존 메모 수천 장을 마이그레이션할 필요가 없다.
- 고른 색은 단색 하나다. 노랑처럼 id 해시로 단계를 나누지 않는다. 사용자가 "정신 사납다"고 했으니 고른 색은 고른 그대로 보인다.
- 고르는 UI는 Radix ContextMenu 하위 메뉴다. 판 모양 하위 메뉴와 같은 생김새를 그대로 따른다.

## 구현 메모
- 색 목록 제안: 기본 노랑, 파랑 #e5edf2, 연두 #e8eee0, 보라 #ece5f0, 분홍 1개. 앞의 셋은 globals.css 31~33행 `--color-card-blue/lime/purple` 토큰이다. 분홍은 토큰이 아직 없어 새로 추가한다.
- 저장 값 제안: `"blue" | "lime" | "purple" | "pink"`. 빈 값이면 기본 노랑이다.
- 색조 해석: `memoVariety.ts`의 `memoTint(id)`를 `memoTint(card)` 꼴로 바꿔 `card.color`가 팔레트에 있으면 그 값을, 없으면 해시 노랑을 돌려준다. 파일 머리 주석의 "DB color 칸에는 쓰지 않는다"도 고친다.
- 호출처 2곳: `cards/text/Content.tsx:127`, `table/MemoTable.tsx:358`.
- 상태: `state/workspace.ts`에 `setMemoColor(ids, color)`를 추가한다. 패턴은 `setFrameSkin`(596, 2678행)과 `setTextStyle`(614, 2872행). kind가 text가 아닌 카드는 거른다.
- 메뉴: `DraggableCard.tsx` 1218행 부근 판 모양 하위 메뉴(`FRAME_SKIN_MENU`, `data-frame-skin-*`)를 본뜬다. 대상 id는 이 카드가 `selectedIds`에 있으면 `selectedIds`, 아니면 `[card.id]`다. 764행 드래그 로직과 같은 규칙이다.
- 되돌리기 현황: 일반 undo 스택이 없다. 있는 건 펜 undo(`penUndo`, Canvas.tsx 412행)와 삭제 5초 undo(`undoBoardRemove`, `undoSubcanvasRemove`)뿐이다.
- JSON Canvas 내보내기: `state/export/jsonCanvasExport.ts`에 `color?: string` 타입은 있지만 지금 노드에 값을 안 싣는다. JSON Canvas는 hex 문자열을 허용하므로 팔레트 이름을 hex로 바꿔 text 노드에 싣는다. 기본 노랑은 싣지 않는다.
- 글상자 `setTextStyle`도 같은 `color` 칸을 쓴다. kind가 달라 겹치지 않지만, 해석 함수는 kind가 text일 때만 팔레트로 읽는다.
- 메모 펼침 창 `cards/MemoExpandDialog.tsx`는 `memoTint`를 안 쓴다. 이번 범위 밖이다.
