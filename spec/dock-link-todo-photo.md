# Spec: 하단 도크에 링크·할 일·사진 도구 추가
Started: 2026-10-02

## 목표
하단 도크에 링크, 할 일, 사진 버튼 3개를 더한다.
할 일과 링크는 새 카드 종류 없이 메모 한 장으로 만든다.
사진은 이미 있는 사진 카드로 만든다.

## 비목표
- 새 카드 종류를 만들지 않는다. 화면에 섞이는 카드 모양은 지금 그대로다.
- 옛 할 일·이미지·링크 카드 종류를 되살리지 않는다.
- 할 일 마감일, 알림, 담당자는 넣지 않는다.
- 사진 버튼은 한 번에 여러 장을 고르지 않는다. 여러 장은 지금처럼 드롭으로 한다.
- 링크 입력칸은 주소 한 줄만 받는다. 제목을 손으로 적는 칸은 없다.
- 체크박스 진행률 배지는 이번에 넣지 않는다. 열린 질문으로 둔다.

## 성공 기준
1. 도크에 버튼 3개가 더 보인다. 순서는 메모 다음에 할 일, 링크, 사진이다.
2. 세 버튼에 마우스를 올리면 다른 버튼처럼 확대되고 이름표가 뜬다.
3. 할 일 버튼을 누르면 화면 가운데에 메모 1장이 생긴다.
4. 그 메모는 바로 편집 상태로 열린다. 본문에 빈 체크박스 1개가 있고 커서가 그 안에 있다.
5. 할 일 메모에서 글을 적고 Enter를 누르면 다음 체크박스가 생긴다.
6. 링크 버튼을 누르면 주소 입력칸이 뜨고 포커스가 간다.
7. 주소를 넣고 Enter를 누르면 링크 블록 1개를 담은 메모가 생긴다. 주소 붙여넣기와 결과가 같다.
8. 링크 메모는 미리보기가 오면 제목이 채워진다. 미리보기가 실패해도 주소만으로 남는다.
9. 사진 버튼을 누르면 파일 선택 창이 열린다. 사진을 고르면 사진 카드 1장이 생긴다.
10. 파일 선택을 취소하면 아무 카드도 생기지 않는다.
11. 세 버튼 모두 끌어서 캔버스에 놓으면 놓은 자리에 만든다. 클릭이면 화면 가운데다.
12. 끌어 놓는 위치는 드래그 미리보기 중심과 8px 안에서 맞는다.
13. 새 문구는 모두 ko.json에 있다. 코드에 한국어 문구를 직접 쓰지 않는다.
14. `vitest` 전체가 통과한다. 새 테스트가 최소 3개 늘어난다. 버튼마다 1개다.

## 경계 조건
- 링크 입력이 http, https, mailto 주소가 아니면 메모를 만들지 않는다. 입력칸 아래에 짧은 안내를 띄운다.
- 링크 입력칸은 Esc나 바깥 클릭으로 닫힌다. 닫으면 메모를 만들지 않는다.
- 링크 입력칸 앞뒤 공백은 지운다. 빈 입력에서 Enter는 아무 일도 안 한다.
- 링크 미리보기가 늦게 와도 사용자가 이미 본문을 고쳤으면 덮어쓰지 않는다. 지금 붙여넣기와 같은 규칙이다.
- 사진 형식과 10MB 한도는 사진 카드 스펙을 그대로 따른다. 넘으면 토스트만 띄운다.
- 사진을 끌어 놓은 뒤 파일 창을 열면 놓은 자리를 기억한다. 사진을 고르면 그 자리에 만든다.
- 할 일 메모의 빈 체크박스는 저장 뒤 다시 열어도 체크박스로 남는다.
- 시스템 보드에서도 세 버튼이 동작한다. 생성을 막지 않는다.
- 공유 보드에서 만든 세 카드는 다른 참여자 화면에도 뜬다. 기존 메모·사진 카드 동기화를 그대로 탄다.

## 기술 결정
- 할 일은 메모 본문 마크다운으로 만든다. 에디터가 이미 체크박스 목록을 지원하기 때문이다.
- 링크는 붙여넣기 흐름을 함수 하나로 빼서 도크와 붙여넣기가 같이 부른다. 같은 코드를 두 번 쓰지 않기 위해서다.
- 사진은 숨긴 파일 입력 하나로 고른다. 브라우저 기본 파일 창이면 충분하다.
- 링크 입력칸은 Radix Popover로 띄운다. 기성 디자인 시스템을 쓰지 않는 규칙 때문이다.
- 도크 버튼 id는 새로 만든다. 옛 도구 id를 쓰면 옛 카드 종류로 만들어지기 때문이다.

## 구현 메모
- 도크: `web/src/components/workspace/Dock.tsx`. `DOCK_ITEMS` 59행, 드롭 `tryDrop` 270행대, 클릭 `createAtCenter` 409행. 드래그 미리보기 `DockDragPreview.tsx`.
- 옛 kind 결정: `kindForTool`(state/workspace.ts 896행)이 "checklist"·"image"·"link"를 같은 이름 kind로 돌린다. `components/workspace/cards/` 아래에는 board·frame·photo·text·textbox 렌더러만 있다. checklist는 `markdownMigration.ts`가 텍스트로 옮기는 레거시다. 그래서 옛 id로 `addCardAt`을 부르면 렌더러 없는 카드가 생긴다. 새 도크 id는 `todo`·`link-memo`·`photo` 같은 이름으로 따로 두고 `tryDrop`·`createAtCenter`에서 분기한다. 이름은 구현 때 정한다.
- 드롭 폭 맞춤: `widthForKind(kindForTool(toolId))`. 할 일·링크는 "text" 폭, 사진은 `PHOTO_DEFAULT_WIDTH` 240을 쓰게 한다.
- 할 일: `addCardAt("text", …)` 또는 `addCardAtViewportCenter("text", …)` 뒤 `setContent(id, "- [ ] ")`, `setEditing(id)`. Milkdown gfm이 빈 작업 항목을 그대로 직렬화하는지 테스트로 확인한다. `cards/_shared/editor/formatCommands.ts` 114행.
- 링크: `Canvas.tsx` 277~294행 붙여넣기 본문을 `createLinkMemo(url, at?)` 같은 함수로 뺀다. `serializeBlock({type:"link", url})`가 허용 스킴 밖이면 null을 준다. `fetchLinkPreview`는 `state/cardContent.ts`.
- 사진: `storePhoto(file)`(components/workspace/canvasCapture.ts 158행) 결과를 `addPhotoAt(x, y, photo)`에 넘긴다. 가운데 좌표 계산은 Canvas.tsx 붙여넣기 경로 255~262행과 같다. accept는 png·jpeg·gif·webp·svg.
- 끌어 놓은 뒤 파일 창: pointerup 핸들러 안에서 `input.click()`을 부른다. 사용자 제스처 안이라 브라우저가 막지 않는다.
- 아이콘 후보: `public/icons/sidebar/todo-v2.png`, `link-v2.png`, `image-v2.png`가 이미 있다. 펜·시그널 버튼도 sidebar v2 아이콘을 쓴다.
- 앞면 배지: `MemoFrontBadges.tsx`가 링크 개수를 이미 보인다. 링크 메모는 추가 작업 없이 배지가 뜬다.
