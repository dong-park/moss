# 공유 보드 안 파일함도 같은 멤버에게 열린다

## 목표
공유 보드 안에서 만든 파일함은 따로 공유하지 않아도 그 보드의 멤버가 들어갈 수 있다.
FEAT-collab-auth §10의 "서브 보드는 따로 공유해야 한다"를 뒤집는다. 2026-09-30 사용자 결정.

## 결정
- 멤버 행은 공유 루트 보드에만 둔다. 하위 보드는 `boards.parent_id`로 부모를 기억한다.
- 권한은 부모 체인을 거슬러 올라가 처음 만나는 멤버 행으로 판단한다. server `roleOf`와 sync 멤버 검사가 같은 규칙을 쓴다.
- 하위 보드 등록은 `POST /boards/{id}/share`에 `parentId`를 실어 보낸다. 부모 체인의 멤버면 편집자도 등록할 수 있다. 소유자는 루트 소유자로 둔다.
- `/me/boards`는 하위 보드도 `parentId`와 함께 돌려준다. 웹은 부모 아래에 원격 사본 행을 만든다.
- 루트 공유 해제는 하위 보드까지 FK cascade로 지운다. sync 연결도 하위까지 끊는다.
- 초대·멤버 목록·내보내기는 하위 보드에서 불러도 루트 기준으로 동작한다.

## 진행
- [x] server: V6 parent_id, roleOf 체인, share parentId, /me/boards 하위 포함, 해제·내보내기 하위까지. 테스트 76개 통과
- [x] sync: 멤버 검사를 재귀 CTE로 부모 체인까지. 테스트 38개 통과
- [x] web: 파일함 생성·공유 시작·syncMyBoards 때 `shareSubBoards`로 등록, `/me/boards` 하위는 부모 아래 원격 사본. 웹 테스트 1369개 통과, 기존 실패 1건은 무관
- [x] 로컬 스택 두 계정 확인: 편집자가 파일함 등록 200, 손자 보드 토큰 200, sync SQL 1행, 루트 해제 뒤 행 0개

## 미룬 것
- 등록 전에 이미 내용이 있던 파일함은 만든 사람이 그 파일함을 한 번 열어야 내용이 서버에 올라간다
- 파일함을 다른 보드로 옮길 때 서버 parent_id 갱신
- 파일함을 지울 때 서버 행 정리
