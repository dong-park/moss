- 미증명: 재현 스크립트 reviewer-repro.ts 자체는 다시 돌리지 않았다. 같은 시나리오를 단위 테스트로 옮겼다.
- 미증명: 새 사용자를 429로 닫는 선택은 내가 정했다. 503이 낫다면 호출자가 정한다.
- 타입 검사: guard, embeddingQueue, authHeaders 관련 오류는 없었다. 기존 CardContent.frame 오류는 그대로다.
- 안 건드린 것: mcp, bridge, auth store, 서버.

## 추가 수정: 보존 메모의 개인정보 결함

- 같은 id를 다시 enqueue하면 보존된 옛 내용을 지운다. 제외 표시와 빈 내용도 포함한다.
- 전역 제외 상태의 flush는 보존된 메모를 모두 취소한다. 해제 뒤에 옛 내용을 보내지 않는다.
- 테스트 3개를 먼저 추가해 실패를 확인했고, 수정 뒤 통과했다. 파일은 embeddingQueue.ts와 embeddingQueue.test.ts다.
- 미증명: reviewer-repro.ts 61~68행은 다시 돌리지 않았다. 같은 시나리오를 단위 테스트로 옮겼다.
