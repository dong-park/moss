# FEAT-drag-tilt · 메모를 끌 때 종이처럼 흔들리기

> 메모 한 장을 끌면 잡은 지점에 매달린 종이처럼 뒤로 처지고, 놓으면 두세 번 흔들리다 선다.

## 1. 목표

지금은 어느 방향으로 끌든 카드가 -1.5도로 똑같이 기운다. 끄는 방향과 속도가 카드 모양에 드러나게 해서 옮기는 동작 자체를 재밌게 만든다. 저장되는 좌표는 한 픽셀도 바뀌지 않는다.

## 2. 범위

### 포함

- 메모 한 장 드래그. 묶음이 아니고 메모판도 아닌 경우다.
- 잡은 지점을 회전축으로 쓴다.
- 가로 속도에 비례해 카드가 끄는 반대쪽으로 처진다. 최대 각도는 상수 하나다.
- 놓으면 스프링으로 2~3회 흔들리다 0도에 선다.
- 함 흡수와 브레드크럼 꺼내기 애니메이션은 놓는 순간의 실제 각도에서 출발한다.
- `prefers-reduced-motion: reduce`이면 지금의 -1.5도 고정 기울기를 그대로 쓴다.

### 제외

- 묶음 드래그와 메모판 드래그. 지금 동작 그대로다.
- 던지기, 스냅, 밀어내기. 좌표를 바꾸는 효과는 전부 뺀다.
- 새 의존성. `motion` v13이 이미 있다.

## 3. 수용 기준

- **AC-1** 메모 한 장을 오른쪽으로 빠르게 끌면 카드가 시계 반대 방향으로 기운다. 왼쪽이면 반대다. 각도 절댓값은 `MAX_TILT_DEG`를 넘지 않는다.
- **AC-2** 끌다가 멈추고 누른 채로 있으면 카드가 0도 근처로 돌아온다.
- **AC-3** 회전축은 잡은 지점이다. `transform-origin`이 카드 로컬 좌표의 누른 위치다.
- **AC-4** 놓으면 흔들림 안착이 끝난 뒤 카드의 `transform`이 비고 `transform-origin`도 기본값으로 돌아온다.
- **AC-5** 함이나 브레드크럼 위에서 놓으면 흡수·꺼내기 모션이 카드 중심 기준으로 정확히 날아간다. 첫 프레임 각도는 놓기 직전 각도와 같다.
- **AC-6** 묶음 드래그와 메모판 드래그의 lift 스타일은 지금과 같다. 기존 `DraggableCard.dragLift.test.tsx` 5개가 통과한다. 단일 메모 lift는 1.03배를 CSS 변수 폴백으로 받는다.
- **AC-7** reduced-motion이면 누르는 순간 설정을 한 번 읽고, AC-1~4 대신 지금의 고정 기울기와 170ms 안착이 나온다.
- **AC-8** 드래그 중 기울기 갱신이 스토어에 쓰지 않는다. 한 번 움직일 때 스토어 쓰기 횟수가 지금과 같다.

## 4. 태스크

- **T1 속도 스무딩과 각도 계산**: 순수 함수로 뺀다. 입력은 이전 각도, 가로 이동량, 경과 ms다. 출력은 다음 각도다. 트랙패드 mousemove 간격이 고르지 않으므로 지수 이동평균으로 떨림을 누른다. 수용 기준: 단위 테스트로 부호, 상한, 정지 시 0 수렴, 들쭉날쭉한 dt 입력에서 부호가 뒤집히지 않음을 확인한다.
- **T2 드래그 중 적용**: 단일 메모 경로 `onMove`에서 T1 결과를 `containerRef`에 직접 쓴다. rAF 한 번으로 묶는다. 수용 기준: AC-1·2·3·8. 급소 실험도 여기서 한다. 실제 브라우저에서 메모를 5초 끌며 mousemove 간격과 각도를 기록한다. 부호가 떨리면 T3 전에 T1 스무딩 상수를 고친다. 브라우저는 `aside` CLI나 `pharos` 인앱 브라우저로 연다. 둘 다 못 쓰면 "미증명"으로 리포트한다.
- **T3 놓기 흔들림**: `motion`의 spring으로 현재 각도에서 0도로 보낸다. 끝나면 인라인 transform과 origin을 지운다. 수용 기준: AC-4·6.
- **T4 흡수·꺼내기 연결**: `runAbsorb`·`runEject`의 첫 키프레임을 실제 각도로 바꾸고 origin을 중앙으로 되돌린다. 수용 기준: AC-5.
- **T5 reduced-motion 분기**: 수용 기준 AC-7.

## 5. 구현 메모

- 드래그 경로는 `moss/web/src/components/workspace/DraggableCard.tsx:182` `onMove` 하나다. 단일 메모는 `:208` else 가지이고 `moveCard`를 매 이동마다 부른다.
- FEAT-memo-variety와 합성: 흔들림은 메모 고유 각도 위에 얹는다. 안착하면 고유 각도로 돌아온다. 고유 각도에서 -1.5도 더 기우는 고정 lift는 묶음·메모판·reduced-motion에만 남는다.
- 회전축은 `transform-origin`이 아니라 `translate(--px,--py) … translate(-) rotate(고유각)` 조합이다. origin을 옮기면 고유 각도가 있는 메모가 들고 놓을 때 2~3px 튄다.
- 각도는 CSS 변수 `--tilt`·`--px`·`--py`·`--lift-scale`로 쓴다. React는 `transform` 문자열 하나만 소유한다. 처음엔 `el.style.transform`에 직접 썼다가 리뷰 지적으로 바꿨다. React prop과 명령형 코드가 같은 속성을 나눠 쓰면 임계 통과 첫 프레임이 덮이고, lift 스타일을 고치는 사람이 그 규칙을 알아야 했다.
- `-1.5deg`가 박힌 곳은 `:254` `runAbsorb`, `:301` `runEject` 두 곳이다. 이동 거리 dx·dy는 카드 중심 기준으로 계산한다. 그래서 origin이 잡은 지점이면 빗나간다.
- 묶음은 `moveSelectedBy`, 메모판은 `moveFrame` 경로다. 건드리지 않는다.
- `motion` ^13.2.0이 `package.json`에 있다.
- jsdom에는 `element.animate`가 없다. 기존 코드는 `typeof cardEl.animate !== "function"`으로 건너뛴다. 같은 패턴을 따른다.
- 브랜치는 현재 워크트리 브랜치 `재미있는액션추가`를 쓴다. base는 `main`이다.
- `TILT_TRANSFORM`의 변수 폴백은 항등 변환(`1`, `0deg`)이다. 처음엔 lift 값(1.03, -1.5도)이었다. 변수를 지운 뒤 `tiltActive`가 내려가기 전 한 프레임이 그려져 선 카드가 튀었다.
- lift 종료는 `releaseLift` 한 곳이다. 흡수·꺼내기는 `.finally`로 불러 이동이 거부돼도 기울기가 풀린다.
- 각도 계산은 rAF 한 곳에서만 한다. mousemove에서도 계산하면 포인터 주사율에 따라 각도가 달라진다.
- 안착 스프링은 ref에 쥔다. 안착 중 다시 잡으면 멈추고 기울기 상태를 비운다. 안 그러면 옛 스프링이 새 드래그의 축을 지운다.
- 느낌 상수 `MAX_TILT_DEG` 기본 8, 스프링 강성·감쇠는 파일 상단 상수로 둔다. 손으로 만져 보고 맞춘다.

## 6. 진행 상황

- T1~T5 구현, 5축 리뷰, 재심사 1라운드와 그 수정까지 끝났다. 전체 스위트 851개 중 `Canvas.virtualization` 1건만 실패한다. 이 실패는 main에서도 난다.
- T2 급소 실험은 **미증명**이다. 실제 브라우저에서 끌어 본 적이 없다. `TILT_GAIN`·`TILT_TAU_MS`·`TILT_SPRING`은 손으로 만져 보고 맞춰야 한다.
- 가정: 함 카드도 단독으로 끌면 기운다. 메모판과 묶음만 뺐다.
