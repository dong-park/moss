# Spec: moss 남은 일 정리 + 기능 로드맵
Started: 2026-09-23

## 목표

구현은 끝났지만 눈으로 확인하지 않은 기능을 모두 검증하고, 낡은 문서와 자잘한 결함을 치운다.
그다음 남은 기능 7개를 어떤 순서로 만들지 한 장의 그래프로 정한다.
이 문서는 순서와 경계, 노드별 완료 기준만 정한다.

## 비목표

- 각 기능의 세부 설계는 이 문서에서 하지 않는다. 설계는 각 기능 스펙이 맡는다.
- 새 기능을 추가하지 않는다. 지금 스펙이 있는 기능만 다룬다.
- 협업, 태스크 관리, 캘린더, AI 대필, 정량 지표 대시보드는 다루지 않는다. 제품이 원래 하지 않기로 한 일이다.
- 캔버스를 Canvas2D로 다시 그리는 일은 하지 않는다. 캔버스 스펙이 다음 단계 과제로 미뤄 두었다.

## 성공 기준

1. 브라우저 확인을 기다리던 스펙 7개와 캔버스 성능 확인 1건이 모두 통과나 실패 중 하나로 판정된다.
2. 판정이 끝난 스펙의 상태 줄에 판정 날짜와 결과가 한 줄로 적힌다.
3. 완료된 스펙은 모두 완료 폴더로 옮겨진다. 폐기된 스펙 1개도 정해진 규칙대로 옮겨진다.
4. 스펙 인덱스의 숫자가 실제 파일 수와 정확히 일치한다.
5. 블루프린트 백업 파일 5개가 레포에서 사라진다.
6. 타입 검사, 린트, 전체 테스트가 3회 연속 실행에서 모두 통과한다.
7. 로드맵의 모든 노드가 완료 기준을 가진다. 그래프에는 순환이 없다.

## 경계 조건

- **브라우저 검증**에는 개발 서버와 의존성 설치가 필요하다. 지금 웹 폴더에는 의존성이 깔려 있지 않다. 그래서 환경 준비 노드가 모든 검증 노드보다 먼저다.
- 검증에서 실패가 나오면 그 노드 안에서 고치지 않는다. 실패를 해당 스펙에 적고 작은 수정 노드로 따로 뺀다.
- 플래키 테스트는 5회 반복 실행에서 한 번이라도 결과가 바뀌면 플래키로 본다.
- 결제와 쿼터는 외부 결제 서비스에 의존한다. 결제 서비스 장애 때 메모 기능은 그대로 동작해야 한다. AI 기능만 막힌다.
- 여러 노드가 같은 화면을 건드리면 동시에 진행하지 않는다. 시스템 보드를 건드리는 홈·위젯·모바일 노드가 여기에 해당한다.
- 독에서 숨긴 펜과 시그널스 도구는 해당 기능이 끝날 때까지 숨긴 채로 둔다.

## 상태 모델

스펙 파일 하나는 아래 상태 중 하나만 가진다.

| 상태 | 뜻 | 위치 |
|---|---|---|
| spec | 스펙만 있다 | 본 폴더 |
| in-progress | 일부 구현했다 | 본 폴더 |
| 검증 대기 | 구현은 끝났고 브라우저 확인만 남았다 | 본 폴더 |
| complete | 확인까지 끝났다 | 완료 폴더 |
| 폐기 | 다른 스펙으로 대체됐다 | 완료 폴더 |

합법 전이는 다음과 같다.

- spec → in-progress → 검증 대기 → complete
- 검증 대기 → in-progress. 브라우저 확인에서 실패했을 때다.
- 어느 상태든 → 폐기. 대체 스펙 링크가 반드시 있어야 한다.

불가능한 조합은 다음과 같다.

- complete인데 본 폴더에 남아 있다.
- 검증 대기인데 완료 폴더에 있다.
- 폐기인데 대체 스펙 링크가 없다.
- complete인데 브라우저 확인 기록이 없다. 단, 화면이 없는 순수 로직 스펙은 예외다.

## 로드맵

### 우선순위

- **P0 마무리**: 환경 준비, 브라우저 검증 3묶음, 작은 수정, 문서 정리. 새 기능보다 먼저 한다.
- **P1 핵심 기능**: 홈, 시그널스, 프리미엄. 홈과 시그널스는 DONE 지표 중 Thought Return과 Connection Rate에 직접 닿는다.
- **P2 확장**: AI 파이프라인 잔여, 위젯, 모바일, 서브 캔버스.

### 그래프

```
c0 환경 준비
 ├─ c1 메모 계열 검증 ─┐
 ├─ c2 캔버스 계열 검증 ┼─ c4 문서 정리
 ├─ c3 내보내기·브리지 검증 ┘
 ├─ c5 작은 수정 ── r3 시그널스
 ├─ r4 홈 ── r5 위젯
 │        └─ r6 모바일
 └─ r1 프리미엄 ── r2 AI 파이프라인 잔여
c2 ── r7 서브 캔버스
```

### 노드별 완료 기준

**c0 환경 준비**
- 의존성 설치가 끝나고 개발 서버가 뜬다.
- 타입 검사, 린트, 전체 테스트 결과를 기준선으로 기록한다.
- 전체 테스트를 5회 돌려 플래키 테스트 목록을 확정한다. 목록은 이름과 실패 비율로 적는다.
- 데이터베이스 닫힘 오류 정리가 이미 되었는지 판정한다.

**c1 메모 계열 검증**
- 메모 제목 스펙의 AC-1, AC-4, AC-5, AC-7을 판정한다.
- 앞면 제목 편집과 빈 메모 유지 스펙의 수동 기준을 모두 판정한다.
- 판정마다 화면 캡처 1장 이상을 남긴다.

**c2 캔버스 계열 검증**
- 캔버스 첫 화면 스펙을 판정한다.
- 포스트잇 리디자인의 마지막 노드인 마무리 노드를 판정한다. 시안 대조와 옛 경로 제거가 포함된다.
- 카드 200장에서 이동과 줌을 할 때 프레임률이 60fps를 유지하는지 잰다. 55fps 아래로 떨어지면 실패로 본다.

**c3 내보내기·브리지 검증**
- 내보내기 스펙의 수동 완료 기준을 모두 판정한다. 세 형식 내보내기와 가져오기가 포함된다.
- 브리지 kind 정리 스펙의 AC-7 스모크를 판정한다.

**c4 문서 정리**
- 상태 모델의 불가능한 조합이 하나도 남지 않는다.
- 인덱스는 상태별 개수와 파일 목록을 가진다. 개수는 실제 파일 수와 같다.
- 인덱스의 작업 분배 절은 이 문서의 로드맵으로 바꾼다.

**c5 작은 수정**
- 테스트 설정에 React act 환경 플래그를 켠다. 켠 뒤 act 경고가 0건이다.
- 빌드 전에 i18n 검사가 자동으로 돈다. 누락 키가 있으면 빌드가 실패한다.
- 블루프린트 백업 파일 5개를 지운다.
- 시그널스 린트 오류 2곳이 0건이 된다.

**r1 프리미엄**
- 무료 사용자가 쿼터를 다 쓰면 AI 호출만 막힌다. 메모 작성·편집·검색은 그대로 된다.
- 결제 완료 웹훅을 받으면 10초 안에 Pro 상태가 반영된다.
- 페이월 3종이 각자의 진입 조건에서만 뜬다.
- 쿼터 게이트 stub이 코드에서 사라진다.

**r2 AI 파이프라인 잔여**
- 서명이 틀린 토큰으로 부른 AI 엔드포인트는 401을 돌려준다.
- 쿼터를 넘긴 호출은 외부 API를 부르지 않고 거절된다.
- 외부 API 일시 오류는 정확히 1회 재시도한다.

**r3 시그널스 잔여**
- 패널이 4개 섹션을 모두 보여준다.
- 키워드를 누르면 해당 메모만 강조되고 나머지는 흐려진다.
- 숨긴 섹션은 24시간 동안 다시 나오지 않는다.
- 독에서 시그널스 도구가 다시 보인다.

**r4 홈 잔여**
- 시스템 보드가 큐레이팅 카드 4종을 모두 보여준다.
- 시스템 보드에 도구를 떨어뜨리면 새 보드 제안 토스트가 뜬다.
- 큐레이팅 카드는 Delete 키로 지워지지 않는다.
- 숨긴 카드는 24시간 동안 다시 나오지 않는다.

**r5 위젯**
- 위젯 3종이 시스템 보드 안에서 홈 카드와 겹치지 않고 보인다.
- 위젯 데이터는 자체 조회로 가져온다. 홈 선택자에 기대지 않는다.

**r6 모바일**
- 화면 폭 768px 이하에서 모바일 피드가 기본 화면이 된다.
- 하단 캡처 바로 쓴 메모가 데스크톱 캔버스에도 나타난다.

**r7 서브 캔버스**
- 캔버스에 함을 놓고 들어가면 새 캔버스가 열린다.
- 브레드크럼으로 한 단계씩 돌아 나올 수 있다.
- 함 안의 카드 수가 함 겉면에 보인다.

## 기술 결정

- **브라우저 검증 도구는 `/prove`를 기본으로 한다.** 캡처와 판정 기록을 한 번에 남길 수 있어서다. 열린 질문 1번에서 확정한다.
- **폐기 스펙도 완료 폴더로 옮긴다.** 본 폴더를 "아직 할 일"만 남기는 곳으로 쓰기 위해서다. 열린 질문 2번에서 확정한다.
- **검증 3묶음을 기능 계열로 나눈다.** 같은 화면을 보는 확인을 한 번에 몰아 개발 서버 재시작과 데이터 준비를 줄이려는 것이다.
- **시그널스 린트는 작은 수정 노드로 뺀다.** 5분짜리 수정이 큰 기능 노드에 묶여 늦어지는 것을 막으려는 것이다.
- **위젯과 모바일은 홈 뒤에 둔다.** 셋 다 시스템 보드 화면을 건드려서 동시에 하면 충돌한다.

## 열린 질문

1. 브라우저 검증을 무엇으로 할까? 기본안은 `/prove`로 판정과 캡처를 남기는 것이다.
2. 폐기 스펙을 어디에 둘까? 기본안은 완료 폴더로 옮기고 상태 줄에 폐기와 대체 링크를 남기는 것이다.
3. 펜 도구는 언제 독에 다시 보일까? 숨긴 이유가 커밋에 적혀 있지 않다. 기본안은 c1 검증 뒤 펜 동작을 따로 확인하고 다시 보이는 것이다.
4. 서브 캔버스를 이번 로드맵에 넣을까? 블루프린트에 아직 등록되지 않았다. 기본안은 P2로 넣고 블루프린트 등록을 r7 첫 작업으로 하는 것이다.
5. DONE 기준인 지표 5개를 누가 재나? 지금 로드맵에는 지표 측정 노드가 없다. 기본안은 r4 뒤에 지표 측정 노드를 따로 스펙으로 만드는 것이다.
6. 프리미엄을 모바일보다 먼저 할까? 기본안은 먼저 하는 것이다. AI 파이프라인 잔여가 프리미엄을 기다리고 있어서다.
