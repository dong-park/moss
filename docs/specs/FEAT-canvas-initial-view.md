# FEAT-canvas-initial-view · 첫 화면은 딱 화면만큼, 줌은 80~110%

> 앱을 열면 캔버스가 멀리 줌아웃된 채로 보이지 않는다. 지금 화면에 보이는 만큼만 보여 주고, 확대·축소는 80%에서 110% 사이로만 된다.

## 1. 목표 (Job Statement)

moss를 처음 연 사람이 캔버스가 지나치게 넓고 메모가 작게 보여 당황하지 않게 한다. 첫 화면은 브라우저 창 크기만큼의 영역을 거의 실제 크기로 보여 준다. 확대·축소 범위는 우선 80%에서 110%로 좁히고, 값은 나중에 한 곳에서 고칠 수 있게 둔다.

## 2. 범위

### 포함 (in-scope)

- 줌 하한을 80%로, 상한을 110%로 바꾼다.
- 줌 한계는 상수 두 개로 둔다. 다른 곳에 숫자를 따로 적지 않는다.
- 첫 화면 맞춤이 80%보다 작게 줄이지 않는다.
- 줌 바의 −, + 버튼은 한계에 닿으면 누를 수 없게 된다.
- 휠, 트랙패드 핀치, 줌 바 버튼, 100% 버튼, 원점 복귀가 모두 같은 한계를 따른다.
- 보드를 오가며 되살린 화면도 한계 안으로 맞춘다.

### 제외 (비목표)

- 팬 이동 범위는 이번에 막지 않는다. 캔버스는 지금처럼 어느 방향으로나 끌 수 있다. 막을지는 §9에서 정한다.
- 줌 단축키를 새로 만들지 않는다. 지금 캔버스 줌 단축키는 없다. 브라우저 자체 확대는 moss가 건드리지 않는다.
- 모바일 화면은 다루지 않는다. 768px 이하에서는 캔버스 대신 피드가 뜬다. [[FEAT-mobile]] 범위다.
- 줌 바의 모양과 위치는 바꾸지 않는다. [[FEAT-sticky-redesign]]의 레이아웃 규칙을 그대로 따른다.
- "100%" 버튼이 화면 왼쪽 위를 기준으로 줌하는 기존 동작은 고치지 않는다.

## 3. 수용 기준 (Acceptance Criteria)

### AC-1 — 첫 화면이 화면 크기만큼이다

- **Given** 메모가 넓게 흩어져 있어 전부 담으려면 25%까지 줄여야 하는 캔버스가 있다.
- **When** 새로고침해 앱을 연다.
- **Then** 첫 화면 줌은 80% 이상 100% 이하다.
- **And** 화면에 보이는 캔버스 영역은 창 크기의 1.25배를 넘지 않는다.
- **And** 캔버스 쪽에 스크롤바가 생기지 않는다.

### AC-2 — 메모가 가까이 모여 있으면 그대로 맞춘다

- **Given** 메모 4장이 창 안에 다 들어가는 캔버스가 있다.
- **When** 앱을 연다.
- **Then** 메모 4장이 모두 화면 안에 보인다.
- **And** 줌은 100%를 넘지 않는다.

### AC-3 — 휠과 핀치는 한계에서 멈춘다

- **Given** 줌이 100%다.
- **When** 휠이나 트랙패드 핀치로 계속 줄인다.
- **Then** 줌은 80%에서 멈춘다.
- **When** 이어서 계속 키운다.
- **Then** 줌은 110%에서 멈춘다.
- **And** 한계에서 더 굴려도 화면 위치가 흔들리지 않는다.

### AC-4 — 줌 바가 한계를 보여 준다

- **Given** 줌이 100%다.
- **When** −를 누른다.
- **Then** 줌은 83%가 된다. 한 번 더 누르면 80%가 되고 −는 누를 수 없게 된다.
- **When** +를 누른다.
- **Then** 줌은 110%가 되고 +는 누를 수 없게 된다.
- **And** 가운데 숫자는 언제나 80에서 110 사이의 정수를 보여 준다.

### AC-5 — 되살린 화면도 한계 안이다

- **Given** 보드 A의 화면 정보가 한계 밖 값으로 남아 있다.
- **When** 보드 A로 돌아간다.
- **Then** 줌은 80%에서 110% 사이로 맞춰진다.

### AC-6 — 새 메모는 화면 안에 생긴다

- **Given** 앱을 막 열어 첫 화면 맞춤이 끝났다.
- **When** 독에서 메모를 누르거나 Enter로 만든다.
- **Then** 새 메모는 화면 가운데 근처, 보이는 영역 안에 생긴다.
- **And** 80%와 110% 두 줌에서 모두 그렇다.

## 4. 경계 조건

### 입력 범위

- 줌 값은 0.8 이상 1.1 이하다. 어떤 경로로 들어온 값이든 이 범위로 자른다.
- 메모가 0장이면 첫 화면 맞춤을 하지 않는다. 줌 100%, 원점에서 시작한다.
- 메모가 1장이면 100%로 그 메모를 가운데에 둔다. 지금처럼 100% 넘게 키우지 않는다.

### 화면 크기 변화

- 창 크기를 바꿔도 줌은 그대로다. 첫 화면 맞춤은 앱을 열 때 한 번만 한다.
- 시그널스 패널이 열려 캔버스 폭이 줄어도 줌은 그대로다. 보이는 영역만 좁아진다.
- 캔버스 폭이 769px에서 1000px 사이면 메모가 다 안 들어올 수 있다. 이때도 80% 밑으로 줄이지 않는다.

### 동작 줄이기

- 줌과 팬은 지금도 애니메이션 없이 바로 바뀐다. 사용자가 동작 줄이기를 켜도 이 기능은 달라지는 게 없다.
- 독 확대에 대한 동작 줄이기 규칙은 [[FEAT-sticky-redesign]] §4를 그대로 따른다.

### 실패 모드

- 캔버스 크기를 아직 못 쟀으면 첫 화면 맞춤을 미룬다. 지금 규칙을 그대로 쓴다.
- 한계를 바꾼 뒤에도 기존 메모 좌표는 그대로다. 저장된 데이터를 옮기지 않는다.

## 6. 기술 결정

- **줌 한계는 상태 모듈의 기존 상수 두 개를 고친다.** 줌 바와 줌 함수가 이미 이 상수를 읽는다. 새 설정 파일을 만들면 읽는 곳이 둘로 갈린다.
- **첫 화면 맞춤은 없애지 않고 하한만 새 상수에 맡긴다.** 맞춤 함수는 이미 하한 상수로 자르고 있다. 상수만 바뀌면 80% 밑으로 내려가지 않는다.
- **맞춤의 상한 1은 그대로 둔다.** 메모 한 장을 110%로 키워 여는 것은 첫인상으로 과하다. §9에서 바꿀 수 있다.
- **줌 바 버튼 한 칸은 1.2배 그대로 둔다.** 범위가 좁아 두 번이면 끝에 닿는다. 더 촘촘히 할지는 §9다.

## 8. 비기능 요구사항

- **성능**: 줌과 팬의 프레임 규칙은 [[FEAT-sticky-redesign]] §8과 [[FEAT-canvas]] 기준을 그대로 따른다. 이번 변경으로 렌더 횟수가 늘지 않는다.
- **접근성**: 누를 수 없게 된 −, + 버튼은 disabled 속성을 갖는다. 화면 읽기 프로그램이 "사용할 수 없음"으로 읽는다.
- **i18n**: 새 글자가 없다.

## 9. 결정된 사항 (2026-09-19 사용자 결정 — 제안 채택)

1. **첫 화면 줌**: 메모에 맞추되 80~100% 사이로 연다. 항상 100%로 열지는 않는다.
2. **팬 범위**: 줌만 제한하고 캔버스 끌기는 자유로 둔다. 영역 밖 기존 메모에 닿을 수 있게.
3. **줌 한계 값**: 80%와 110%로 간다. 바꿀 값이 생기면 상수 두 개만 고친다.
4. **줌 바 한 칸 크기**: 한 번에 20%(1.2배) 그대로 둔다.

## 10. 검증 방법 (DOD)

- `pnpm tsc --noEmit`이 통과한다.
- `pnpm vitest run`이 통과한다. 새 테스트는 아래 네 가지다.
  - 줌 함수와 줌 설정 함수가 0.8 아래와 1.1 위를 자른다.
  - 맞춤 함수가 넓게 흩어진 메모에도 0.8 밑으로 내려가지 않는다.
  - 줌 바의 −는 80%에서, +는 110%에서 누를 수 없다.
  - 보드 전환으로 되살린 화면의 줌이 범위 안이다.
- 수동 시나리오 5개를 1440×900 창에서 돌린다.
  - 메모를 멀리 흩어 둔 캔버스를 새로고침한다. 줌이 80% 이상이다.
  - 휠로 끝까지 줄이고 끝까지 키운다. 80%와 110%에서 멈춘다.
  - 트랙패드 핀치로 같은 확인을 한다.
  - 80%와 110%에서 독으로 메모를 만든다. 둘 다 화면 안에 생긴다.
  - 시그널스 패널을 열고 닫는다. 줌 값이 바뀌지 않는다.

## 11. 구현 메모

- 현재 줌 한계: `web/src/state/workspace.ts:199` `MIN_SCALE = 0.25`, `:200` `MAX_SCALE = 3`. [[FEAT-canvas]] §2의 "25%~300%"가 출처다. 이 스펙이 그 줄을 대체한다.
- 초기 viewport: `workspace.ts:1120` `{ x: 0, y: 0, scale: 1 }`. 고정 크기 월드는 없다. 캔버스는 `Canvas.tsx:530` `overflow-hidden` + `:540` transform 한 겹이라 스크롤바도 원래 없다.
- "초반부터 너무 넓다"의 원인: `Canvas.tsx:145-153`이 첫 로드에 `fitToCards`를 1회 호출한다. `workspace.ts:2309`가 `clamp(min(w/boxW, h/boxH), MIN_SCALE, 1)`이라 흩어진 메모면 25%까지 줄어든다. `MIN_SCALE`만 0.8로 바꾸면 해결된다.
- 줌 경로: 휠·트랙패드 핀치는 `Canvas.tsx:383-397` → `zoomAt`(`workspace.ts:1993`, clamp 후 같은 값이면 상태 불변). 줌 바는 `setScale`(`:2003`). 원점 복귀는 `resetViewport`(`:2008`, scale 1). 모두 `MIN_SCALE`/`MAX_SCALE`만 읽는다.
- 줌 바: `ZoomBar.tsx:6` `ZOOM_STEP = 1.2`, `:24`/`:38` disabled 판정이 `MIN_SCALE + 0.001`/`MAX_SCALE - 0.001`. 1 → 0.833 → 0.8, 1 → 1.1(clamp).
- 보드 복원: `workspace.ts:1194` `viewportByBoard[id] ?? {...}`를 그대로 set 한다. clamp가 없으므로 AC-5를 위해 복원 시 scale clamp를 한 줄 넣는다. `viewportByBoard`는 메모리에만 있고 persist 되지 않는다.
- 새 메모 위치: `addCardAtViewportCenter`(`workspace.ts:1398`) → `avoidCenterOverlap`(`:660`). 화면 중심 → 월드 변환이라 줌 값과 무관하게 화면 안에 생긴다. 메모판은 `:1500`, 보드는 `:2084`에서 같은 경로다.
- 키보드 줌 단축키 없음: `useShortcuts.ts`·`useBoardShortcuts.ts`에 +/-/0 줌 바인딩이 없다.
- 동작 줄이기: 캔버스 world layer의 transition은 opacity만이다(`Canvas.tsx:538`). 줌 전환 애니메이션이 없어 추가 처리가 필요 없다.
- 테스트 위치 후보: `web/src/state/__tests__/workspace.test.ts`, `web/src/components/workspace/__tests__/`. 기존 테스트 중 0.25·3을 직접 단언하는 곳은 없다.
- 노드 3개(상수 변경, 복원 clamp, 테스트)라 plan DAG 문서는 만들지 않았다.
