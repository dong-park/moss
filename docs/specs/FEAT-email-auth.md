# FEAT-email-auth · 메일로 회원가입·로그인

> Google 계정이 없거나 쓰기 싫은 사람도 메일과 비밀번호로 가입해 moss를 쓴다. 메일 인증은 이번에 하지 않는다.

**Status**: spec 작성 (2026-09-29)
**Estimated**: M
**의존**: [[FEAT-onboarding-routes]] — 로그인 온보딩 화면(`LoginOnboarding`)에 메일 폼을 붙인다. 그 브랜치가 병합된 뒤 시작한다.

---

## 1. 목표

moss는 로그인해야 쓴다([[FEAT-onboarding-routes]] D5). 지금 로그인 수단은 Google 하나라서 Google 계정이 없는 사람은 첫 화면에서 막힌다. 메일과 비밀번호로 가입과 로그인을 할 수 있게 한다.

## 2. 범위

### 포함
- 메일·비밀번호·이름으로 회원가입
- 메일·비밀번호로 로그인
- 로그인 온보딩 화면에 메일 폼 추가
- 로그인 시도 횟수 제한

### 제외
- 메일 인증 — 11절
- 비밀번호 재설정 — 11절
- Google 계정과 메일 계정 합치기 — 11절
- 비밀번호 변경·회원 탈퇴 화면 — 11절

## 3. 현재 상태

- 서버는 Ktor다. 인증 라우트는 `POST /auth/google`과 `POST /auth/refresh` 두 개다.
- 두 라우트 모두 `AuthResponse { accessToken, refreshToken, user }`를 돌려준다.
- `users` 테이블 칸은 `id uuid`, `google_sub text not null unique`, `name`, `avatar`, `created_at`이다.
- 메일 칸이 없다. Google 로그인도 메일을 저장하지 않는다.
- 비밀번호 해시 라이브러리가 없다. JWT는 `com.auth0:java-jwt`, DB 이전은 Flyway `V1`~`V4`다.
- 웹은 `LoginOnboarding`에 `GoogleButton` 하나를 둔다. 세션 저장은 `state/auth`의 `tokenStore`가 한다.

## 4. 결정

| # | 결정 | 근거 |
|---|------|------|
| D1 | `users`에 `email text unique`, `password_hash text`를 더하고 `google_sub`를 nullable로 바꾼다. `google_sub`와 `password_hash` 중 하나는 반드시 있다는 check 제약을 건다. Flyway `V5` | 사용자 테이블을 둘로 나누면 보드·멤버 외래키가 두 갈래가 된다 |
| D2 | 메일은 앞뒤 공백을 지우고 소문자로 바꿔 저장·비교한다 | `A@x.com`과 `a@x.com`이 두 계정이 되지 않게 한다 |
| D3 | 해시는 bcrypt, cost 12. 라이브러리는 `at.favre.lib:bcrypt` | 순수 자바라 추가 네이티브 의존이 없다 |
| D4 | 비밀번호는 8자 이상, UTF-8로 72바이트 이하 | bcrypt는 72바이트 뒤를 버린다. 잘리는 걸 모르고 쓰게 두지 않는다 |
| D5 | `POST /auth/signup {email, password, name}`, `POST /auth/login {email, password}`. 둘 다 기존 `AuthResponse`를 돌려준다 | 웹의 토큰 저장·갱신 경로를 그대로 쓴다 |
| D6 | 로그인 실패는 메일이 없든 비밀번호가 틀리든 같은 문구 "메일이나 비밀번호가 맞지 않아요", 같은 401. 메일이 없어도 가짜 해시와 비교해 응답 시간을 맞춘다 | 가입된 메일을 캐 볼 수 없게 한다 |
| D7 | 가입 때 이미 있는 메일이면 409 "이미 가입된 메일이에요" | 가입 화면에서는 알려 줘야 사람이 로그인으로 간다. 메일 인증이 없어 이 노출은 받아들인다 |
| D8 | 시도 제한: 로그인은 IP+메일당 1분 10회, 가입은 IP당 1시간 20회. 넘으면 429 "잠시 뒤 다시 시도해 주세요". Ktor `RateLimit` 플러그인, 메모리 저장 | 비밀번호 대입을 막는다. 서버가 1대라 메모리로 충분하다 |
| D9 | 메일 인증이 없으므로 `email_verified_at`은 칸만 만들고 늘 null로 둔다 | 나중에 인증을 붙일 때 이전 없이 채운다 |
| D10 | Google 계정과 메일 계정은 메일이 같아도 별개 계정이다 | Google 쪽은 메일을 저장하지 않는다. 인증 없는 메일로 합치면 남의 Google 계정을 가로챌 수 있다 |
| D11 | 웹 온보딩: Google 버튼 아래 "메일로 계속" 링크. 누르면 로그인 폼이 열리고 "처음이에요? 가입하기"로 가입 폼으로 바꾼다. 가입 폼은 메일·비밀번호·이름 3칸 | 첫 화면에 칸 3개가 보이면 Google 버튼이 묻힌다 |
| D12 | 이름은 1~40자. 아바타는 없고 기존 멤버 아바타가 이름 첫 글자로 대신한다 | 가입 칸을 늘리지 않는다 |

## 5. 수용 기준

### AC-1 — 회원가입
- **Given** 로그인 온보딩 화면이다
- **When** "메일로 계속" → "가입하기" → 메일·8자 이상 비밀번호·이름을 넣고 가입한다
- **Then** 바로 로그인된다. 보드가 없으면 첫 보드 고르기 화면이 뜬다([[FEAT-onboarding-routes]] AC-5).

### AC-2 — 로그인
- **Given** 메일로 가입한 계정이 있다. 로그아웃했다
- **When** 같은 메일과 비밀번호로 로그인한다
- **Then** 마지막 보드가 열린다. 새로고침해도 로그인이 유지된다.

### AC-3 — 메일 대소문자
- **Given** `Moss@Example.com`으로 가입했다
- **When** ` moss@example.com `으로 로그인한다
- **Then** 같은 계정으로 로그인된다.

### AC-4 — 틀린 비밀번호와 없는 메일
- **When** 틀린 비밀번호로, 또 가입하지 않은 메일로 각각 로그인한다
- **Then** 둘 다 "메일이나 비밀번호가 맞지 않아요"와 401이다. 서버 응답 시간 차이가 50ms 안이다.

### AC-5 — 중복 가입
- **Given** `a@x.com`이 가입돼 있다
- **When** 같은 메일로 다시 가입한다. 대소문자만 바꿔도 같다
- **Then** "이미 가입된 메일이에요"와 409다. 계정이 새로 생기지 않는다.

### AC-6 — 입력 검사
- 비밀번호 7자, 72바이트 초과, 메일 형식 아님, 이름 빈칸은 서버가 400으로 거절한다.
- 웹 폼은 같은 규칙으로 보내기 전에 칸 아래 안내를 띄운다.

### AC-7 — 시도 제한
- **When** 같은 IP·같은 메일로 1분 안에 로그인을 11번 틀린다
- **Then** 11번째는 429 "잠시 뒤 다시 시도해 주세요"다. 맞는 비밀번호도 1분 동안 429다.

### AC-8 — 비밀번호 보관
- DB의 `password_hash`는 `$2`로 시작하는 bcrypt 문자열이다. 평문이나 평문을 포함한 값은 DB·로그 어디에도 없다.
- 요청 로그(`CallLogging`)에 요청 본문이 찍히지 않는다.

### AC-9 — Google 로그인 회귀
- 기존 Google 계정은 그대로 로그인된다. `V5` 이전 뒤에도 `google_sub` 계정 행이 그대로다.
- 같은 메일을 쓰는 Google 계정과 메일 계정은 서로 다른 보드 목록을 본다(D10).

### AC-10 — 공유와 초대
- 메일 계정 A가 보드를 공유하고 Google 계정 B를 초대한다. B가 수락하면 둘이 함께 편집한다. 반대 방향도 같다.
- 멤버 목록에 A는 이름 첫 글자 아바타로 보인다.

## 6. 엣지 케이스

- **가입 중 새로고침**: 요청이 서버에 닿았으면 계정이 생긴다. 다시 가입하면 AC-5가 뜨고 로그인으로 안내한다.
- **같은 브라우저 다른 계정**: [[FEAT-onboarding-routes]] D5-2 안내 카드가 계정 종류와 상관없이 뜬다.
- **오프라인**: 가입·로그인은 네트워크가 필요하다. 오프라인이면 폼 아래 "연결되면 다시 시도해 주세요"를 띄우고 버튼을 막는다.
- **비밀번호를 잊음**: 이번 범위에는 되찾을 방법이 없다. 로그인 폼에 "비밀번호를 잊었어요" 링크를 두지 않는다. 11절의 재설정이 들어올 때 붙인다.

## 7. 화면

- 로그인 폼: 메일, 비밀번호, "로그인" 버튼, "처음이에요? 가입하기".
- 가입 폼: 메일, 비밀번호, 이름, "가입하기" 버튼, "이미 계정이 있어요".
- 두 폼 모두 위에 "Google로 계속" 버튼이 남는다.
- 비밀번호 칸은 `autocomplete`를 로그인 `current-password`, 가입 `new-password`로 둔다. 메일 칸은 `type="email"`, `autocomplete="email"`.

## 11. 미룬 질문

## 12. 구현 메모

- `upsertUser`는 Google 전용으로 남긴다. 메일 계정용 `createEmailUser`·`findByEmail`을 따로 둔다.
- 가짜 해시는 서버 시작 때 한 번 만들어 둔다. 없는 메일 로그인에서 그 해시와 비교해 시간을 맞춘다.
- `CallLogging`이 본문을 찍는지 확인하고, 찍으면 `/auth/*`를 걸러 낸다.
