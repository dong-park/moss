# FEAT-frame-skins · 메모판 스킨

> 메모판 뒤에 깔리는 그림을 갈아 끼운다. 스킨은 배경 그림일 뿐이다. 메모의 자리·소속·동작은 하나도 바뀌지 않는다.

**Status**: 구현 완료 (WORK)
**Owner**: dong-park
**Estimated**: S
**Started**: 2026-09-26
**Blueprint**: 없음. 새 기능이다. 비목표 문구는 `docs/moss.blueprint.json`의 NON-GOALS를 따른다.

## 1. 목표

메모판을 쓰는 사람이 판 뒤에 "씨앗 / 자라는 중 / 묵힘" 같은 세로 칸 그림을 깔아 두고, 그 위에 메모를 손으로 놓아 생각을 나눠 보고 싶어 한다. 판마다 스킨을 골라 배경 그림만 바꾼다. 이번에는 스킨 틀과 세로 칸 스킨만 만들고, 월달력은 읽히는지 실험만 한다.

## 2. 범위

### 포함

- **스킨 틀.** 판마다 스킨 하나를 고른다. 스킨은 판 뒤에 그리는 배경 그림 하나다.
- 스킨은 두 개다. 지금과 같은 자유 판, 그리고 세로 칸 판.
- 판 우클릭 메뉴에서 스킨을 바꾼다.
- 세로 칸 판은 판 폭을 칸 수로 똑같이 나눈 세로 줄과, 칸마다 위쪽 이름표를 그린다.
- 칸 이름표는 그림의 일부다. 칸을 더하고, 이름을 바꾸고, 지울 수 있다.
- 칸은 2~8개다. 세로 칸 판만 판 최대 폭을 1200에서 2400으로 올린다. 자유 판 상한은 1200 그대로다.
- 예전 판은 자유 판으로 읽는다.
- 월달력 가독성 실험. 코드로 남기지 않고 결과만 이 문서에 적는다.

### 제외

- **메모와 칸의 관계 일체.** 메모가 어느 칸에 속하는지 계산하거나 저장하지 않는다. 놓을 때 칸 가운데로 붙지 않는다. 끄는 동안 칸을 강조하지 않는다. 내보내기에 칸 이름을 적지 않는다. 칸은 그림이고 메모는 그림 위에 놓일 뿐이다.
- 스킨 전환·칸 추가·칸 삭제·판 리사이즈로 메모 옮기기. 메모 좌표는 1px도 바뀌지 않는다.
- **완료 개념.** "완료", "할 일", "진행 중" 같은 기본 칸 이름과 체크 표시를 두지 않는다. 업무 관리는 moss의 비목표다.
- 마감일과 날짜 필드.
- 달력 스킨 구현. 이번에는 실험만 한다.
- 별도 투영 뷰. 자리는 캔버스 좌표 한 벌뿐이다.
- 칸 폭을 칸마다 다르게 조절하기.
- 가로 칸, 2x2 매트릭스, 주간표. 틀만 열어 두고 만들지 않는다.
- 내보내기 변경. 마크다운·JSON Canvas는 그대로다. 판 내용 JSON이 번들·MCP로 그대로 나가는 것 외에 추가 작업이 없다.
- 소속 판 규칙 변경. 메모 중심점이 판 안에 있으면 그 판 소속이라는 규칙은 그대로다.

## 3. 수용 기준

### AC-1 하위 호환
- **Given** 이름만 저장된 예전 판이 있다.
- **When** 앱을 연다.
- **Then** 판은 자유 판으로 보인다. 모양, 이름, 멤버가 이 기능 전과 같다.

### AC-2 알 수 없는 값
- **Given** 판 내용에 모르는 스킨 이름이나 깨진 칸 목록이 들어 있다.
- **When** 판을 읽는다.
- **Then** 모르는 스킨은 자유 판으로 읽는다. 깨진 칸 목록은 기본 칸 세 개로 읽는다. 오류로 멈추지 않는다.

### AC-3 스킨 전환 메뉴
- **Given** 자유 판이 있다.
- **When** 판을 우클릭해 "판 모양 → 세로 칸"을 고른다.
- **Then** 판 뒤에 칸 세 개가 그려진다. 이름은 "씨앗", "자라는 중", "묵힘"이다.
- **And** 판 안팎 모든 메모의 x, y와 판 소속이 전환 전과 같다.
- **And** 다시 "자유"를 고르면 칸 그림이 사라진다. 한 번 더 "세로 칸"을 고르면 전에 쓰던 칸 이름이 돌아온다.

### AC-4 전환 때 판 넓히기
- **Given** 폭이 칸 수 × 240보다 좁은 판이 있다.
- **When** 세로 칸으로 바꾼다.
- **Then** 판 폭이 칸 수 × 240으로 늘어난다. 왼쪽 위 모서리는 그대로다. 메모는 움직이지 않는다.
- **And** 넓힌 뒤 소속 판 계산을 다시 한다. 결과는 판을 손으로 같은 크기로 늘렸을 때와 같다.

### AC-5 칸 배경
- **Given** 칸 N개인 세로 칸 판이 있다.
- **When** 화면에 그린다.
- **Then** 칸 경계선이 N−1개 보인다. 경계는 판 폭을 N등분한 자리에 있다.
- **And** 칸 이름표는 줌을 줄여도 화면에서 11px보다 작아지지 않는다.
- **And** 칸 배경은 메모보다 아래에 그려진다. 메모 클릭과 드래그를 막지 않는다. 빈 곳 드래그로 판을 옮기는 지금 동작도 그대로다.

### AC-6 칸 추가
- **Given** 칸 N개인 판이 있고 N은 8보다 작다.
- **When** 칸 머리의 "+"를 누른다.
- **Then** 오른쪽 끝에 이름 빈 칸이 생기고 바로 이름 편집 상태가 된다.
- **And** 판 폭이 (N+1) × 240보다 좁으면 그만큼 오른쪽으로 넓어진다. 메모는 움직이지 않는다.
- **And** N이 8이면 "+"가 보이지 않는다.

### AC-7 칸 이름 바꾸기
- **Given** 세로 칸 판이 있다.
- **When** 칸 이름표를 두 번 누르고 새 이름을 쓴 뒤 Enter를 누른다.
- **Then** 이름이 바뀌고 저장된다. 앞뒤 공백은 지우고 20자까지만 남긴다.
- **And** Esc를 누르면 이름이 바뀌지 않는다.
- **And** 빈 이름은 저장할 수 있다. 화면에는 흐린 "이름 없는 칸"이 보인다.

### AC-8 칸 삭제
- **Given** 칸 N개인 판이 있고 N은 2보다 크다.
- **When** 가운데 칸 머리의 지우기를 누른다.
- **Then** 칸이 N−1개가 되고 판 폭은 그대로다. 남은 칸들이 판 폭을 다시 똑같이 나눈다.
- **And** 메모 좌표와 판 소속은 그대로다.
- **And** N이 2이면 지우기가 보이지 않는다.

### AC-9 판 크기 조절
- **Given** 칸 3개인 판이 있다.
- **When** 판 폭을 900에서 1200으로 늘린다.
- **Then** 칸 폭이 300에서 400으로 늘어난다. 메모 좌표는 그대로다.
- **And** 세로 칸 판은 칸 수 × 240보다 좁게 줄일 수 없다.

### AC-10 판 폭 상한
- **Given** 칸 8개인 세로 칸 판이 있다.
- **When** 판 폭을 오른쪽으로 끝까지 늘린다.
- **Then** 판 폭은 2400에서 멈춘다.
- **And** 자유 판은 지금처럼 1200에서 멈춘다.
- **When** 폭 1920인 세로 칸 판을 자유로 바꾼다.
- **Then** 판 폭은 1920 그대로다.
- **And** 이 판은 줄일 수는 있지만 1920보다 넓힐 수는 없다. 1200 아래로 줄이면 그때부터 상한은 1200이다. 리사이즈 핸들을 잡는 순간 판이 튀지 않는다.

### AC-11 이름 바꾸기가 스킨을 지우지 않음
- **Given** 칸 이름을 바꾼 세로 칸 판이 있다.
- **When** 판 이름을 바꾼다.
- **Then** 스킨과 칸 목록이 그대로 남는다.

### AC-12 번들 왕복
- **Given** 세로 칸 판이 있는 보드를 .moss 번들로 내보낸다.
- **When** 다시 들여온다.
- **Then** 스킨, 칸 이름, 칸 순서가 같다.

## 4. 의존성

- **의존**: FEAT-sticky-redesign의 메모판. 판 카드, 소속 판 계산, 판 이동을 그대로 쓴다.
- **의존**: 줌 역보정 유틸. 칸 이름표가 줌아웃에서도 읽히게 한다.
- **의존받음**: 다음 스펙의 달력 스킨. 이 스펙의 실험 결과로 할지 말지 정한다.
- 외부 라이브러리 추가 없음.

## 5. 데이터 모델

DB 스키마는 바꾸지 않는다. 판 카드의 내용 JSON만 넓힌다.

```ts
type FrameSkinId = "free" | "columns";

interface FrameColumn {
  id: string;   // 화면 key 전용
  name: string; // trim, 최대 20자, "" 허용
}

interface FrameContentJson {
  name?: string;            // 기존. trim, 최대 40자
  skin?: FrameSkinId;       // 없으면 "free"
  columns?: FrameColumn[];  // skin이 free여도 지우지 않고 보관한다
}
```

## 6. 인터페이스

### 스킨 레지스트리

스킨은 배경 컴포넌트 하나와 최소 폭 규칙만 가진다. 계산 로직은 없다.

```ts
// state/frameSkins.ts — React 없음
interface FrameSkinDef {
  id: FrameSkinId;
  /** 이 스킨에서 판이 가질 수 있는 최소 폭 */
  minWidth(cfg: FrameContentJson): number;
  /** 이 스킨에서 판의 최대 폭. 자유 판은 max(1200, currentWidth) — AC-10 */
  maxWidth(cfg: FrameContentJson, currentWidth?: number): number;
}
// cards/frame/skins/ — id → 배경 컴포넌트
```

### Store 액션

- `setFrameSkin(id, skin)` — 스킨을 바꾼다. 세로 칸으로 바뀌면 AC-4대로 판을 넓힌다.
- `addFrameColumn(id)` — 오른쪽 끝에 칸을 더한다. 최대 8개다.
- `renameFrameColumn(id, columnId, name)` — 칸 이름을 바꾼다.
- `removeFrameColumn(id, columnId)` — 칸을 지운다. 최소 2개다.
- `renameFrame` — 이름만 바꾸고 나머지 내용은 그대로 둔다.

### 인코딩

- `encodeFrameContent`가 이름만이 아니라 내용 전체를 받는다.
- `decodeFrameConfig(content)`를 새로 둔다. 스킨과 칸 목록을 정규화해 돌려준다.

## 7. 시각과 인터랙션

- 우클릭 메뉴의 "이름 변경" 아래에 "판 모양" 하위 메뉴를 둔다. 항목은 "자유"와 "세로 칸"이다. 지금 스킨에 체크가 붙는다.
- 칸 경계는 판 테두리와 같은 색의 옅은 세로선이다. 칸 머리는 판 이름표 아래 한 줄이다.
- 칸 머리에 마우스를 올리면 지우기가 보인다. 마지막 칸 머리 오른쪽에 "+"가 있다.

## 8. 비기능 요구사항

- **성능**: 줌과 팬 중에 칸 배경은 React로 다시 그리지 않는다. 칸 경계와 이름표 크기는 CSS 변수로만 바뀐다.
- **접근성**: 칸 이름 편집은 키보드로 된다. Enter는 저장, Esc는 취소다. 우클릭 메뉴는 Radix 기본 키보드 이동을 따른다.
- **i18n**: 기본 칸 이름, 메뉴 문구, "이름 없는 칸"은 ko.json 키로 둔다.
- **프라이버시**: 새 데이터 흐름이 없다.

## 9. 월달력 가독성 실험

달력 스킨을 만들기 전에, 한 달 칸 그림 위에 메모를 놓으면 읽히는지 먼저 본다. 실험은 버리는 브랜치에서 하고 코드는 합치지 않는다.

### 방법

1. 판 하나를 가로 7칸, 세로 5칸 크기로 키운다. 칸 하나는 240 × 240이다. 판은 1680 × 1260이 된다.
2. 7 × 5 격자와 날짜 숫자만 배경으로 그린다.
3. 기본 폭 240인 메모 20장을 손으로 놓는다. 12칸에 1장, 4칸에 2장씩 놓는다.
4. 화면 1440 × 900에서 판 전체가 보이는 줌으로 맞춘다. 예상 줌은 0.68 안팎이다.
5. 같은 판에서 메모를 0.5배로 줄여 그리는 변형도 한 번 본다.

### 통과 조건

다섯 개를 모두 지켜야 통과다.

- 날짜 숫자가 화면에서 11px 이상이다.
- 메모 20장 모두 제목 첫 줄이 화면에서 11px 이상이고 잘리지 않는다.
- 한 칸에 2장 넣은 칸에서 두 메모가 칸 그림 밖으로 넘치지 않는다.
- 판 폭이 2400 이하다.
- 판 전체가 보이는 줌에서 1초 동안 팬하면 프레임 시간 p95가 16ms 이하다.

### 결과에 따른 다음 선택

- 기본 크기로 통과하면 다음 스펙에서 달력 스킨을 만든다.
- 0.5배 변형만 통과하면 "달력 판에서는 메모를 작게 그린다"를 전제로 다음 스펙을 쓴다.
- 둘 다 떨어지면 달력을 접고 주간표를 검토한다.

### 결과

브리프 지시로 **미실시**. 버려진 브랜치에서 브라우저 눈 판정이 필요한 실험이라 runner WORK 범위 밖이다.

## 12. 구현 메모

- 판 내용 인코딩 단일 소스는 `web/src/state/frameContent.ts`다. 지금 `encodeFrameContent(name)`은 이름만 받는다.
- 함정: `renameFrame`은 `encodeFrameContent(name)`으로 내용을 통째로 덮어쓴다. 그대로 두면 판 이름을 바꿀 때 스킨과 칸이 사라진다. AC-11이 이것을 막는다.
- 판 내용을 만드는 다른 곳은 `schema.ts`의 `makeFrameNote`다. `cards/frame/Content.tsx`는 이름을 읽는다.
- 판 크기는 `resizeFrame`(~1900행)이 `FRAME_MIN_WIDTH` 240과 `CARD_MAX_WIDTH` 1200으로 자른다. 세로 칸 판의 최소 폭은 칸 수 × 240. 최대 폭은 `FRAME_COLUMNS_MAX_WIDTH` 2400을 새로 두고, 자유 판은 `max(CARD_MAX_WIDTH, 지금 폭)`으로 자른다(AC-10). `CARD_MAX_WIDTH` 자체는 메모·텍스트박스가 쓰므로 바꾸지 않는다.
- `ResizeHandles.tsx`도 ~104행과 ~141행에서 `CARD_MAX_WIDTH`로 자른다. 판 리사이즈 경로가 이 클램프를 타는지 확인하고, 탄다면 같은 스킨별 상한을 써야 한다. 스토어만 고치면 핸들을 끄는 동안 1200에서 멈춘다.
- 손으로 판 크기를 바꾸면 `ResizeHandles.tsx` ~205행이 `resolveMembership`을 부른다. AC-4·AC-6의 자동 넓히기도 같은 호출을 거쳐야 판 소속 결과가 같다.
- 판 기본 크기는 320 × 220이다. 세로 칸으로 바꾸면 AC-4대로 720으로 넓어진다.
- 우클릭 메뉴는 `DraggableCard.tsx` ~1130행 Radix ContextMenu다. frame의 "이름 변경" 항목 아래에 하위 메뉴를 둔다.
- 줌 역보정은 `cards/_shared/zoomLod.ts`의 `zoomCompensatedPx`, 최소 화면 크기는 `ZOOM_MIN_SCREEN_PX` 11이다.
- MCP `notes_list`·번들은 판 내용 JSON을 그대로 싣는다. `skin`·`columns`는 추가 작업 없이 따라간다.
- 기술 결정: 스킨 정의는 `web/src/state/frameSkins.ts`에, 배경 컴포넌트는 `cards/frame/skins/`에 둔다.
- 기술 결정: 스킨을 자유로 바꿔도 `columns`를 지우지 않는다. 다시 세로 칸으로 돌아올 때 이름을 되살리기 위해서다.
- 기술 결정: 칸 폭은 비율을 저장하지 않고 판 폭을 N등분한다.
- 현재 작업 트리에 이 기능과 무관한 미커밋 변경이 많다(Canvas·Dock·MemoTitleRow·zoomLod 등). 새 브랜치에서 작업하고 그 변경은 건드리지 않는다. `zoomLod.ts`는 아직 미추적 파일이다 — 새 브랜치에 없으면 이 기능 커밋에 포함하지 말고 다른 방법으로 11px 하한을 맞춘다.
