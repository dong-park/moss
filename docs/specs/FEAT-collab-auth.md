## 1. 목표 (Job Statement)

혼자 쓰던 보드를 링크 하나로 공유하고, 초대받은 사람이 Google 로그인 한 번으로 들어와 FigJam처럼 함께 편집한다. 공유하지 않은 보드는 지금처럼 기기에만 둔다.

## 2. 범위

### 포함 (in-scope)
- 모든 보드의 원본을 보드당 Yjs 문서 1개로 바꾼다. 혼자 쓰는 보드도 같다.
- 기존 Dexie v6 보드를 첫 실행 때 Yjs 문서로 자동 변환한다.
- Google 로그인. 공유하거나 초대받을 때만 묻는다.
- 초대 링크 발급·재발급. 역할은 소유자와 편집자 둘.
- 커서·드래그·선택을 실시간으로 보여준다.
- 공유 해제와 내보내기. 편집자 기기의 사본을 지우고 한 번 알린다.
- Ktor·Hocuspocus·Postgres를 docker-compose로 로컬에서 띄운다.
- 공유 보드의 첨부 파일을 Ktor가 받아 배포 환경의 디스크 볼륨에 저장한다. D12.

### 제외 (out-of-scope)
- **보기 전용 역할** — 요청이 생기면. 테이블 변경 없이 뒤에 붙인다.
- **종단간 암호화** — Pro 단계. D9.
- **AI 엔드포인트 보호·쿼터** — 공동 편집 다음 단계. [[FEAT-freemium]] [[FEAT-ai-pipeline]]
- **계정 병합** — 혼자 쓰던 다른 기기의 보드를 계정으로 모으지 않는다. D8.
- **메일·알림 발송** — 초대는 링크 복사뿐이다. D10.
- **휴지통의 공유** — 휴지통은 지금처럼 기기 로컬이다. 복구는 문서에 다시 쓰는 것으로 끝난다.
- **배포** — 로컬 동작 확인 뒤 따로 정한다.

## 4. 기본값으로 정한 것

- **기존 데이터 이전**: 새 버전 첫 실행 때 Dexie v6 보드를 Yjs 문서로 자동 변환한다. 원본 Dexie 테이블은 한 버전 동안 남긴다.
- **개발 환경**: Ktor·Hocuspocus·Postgres를 `docker-compose` 하나로 로컬에서 띄운다.
- **PRD 수정**: §4-2·§34-2의 협업 제외 삭제. §23·§1026을 "공유 보드는 서버 평문"으로. §1287 Supabase를 Ktor로.
- **토큰 수명**: 액세스 JWT 15분, 리프레시 JWT 30일, 보드 토큰 1시간. 숫자는 구현 메모에 근거를 둔다.
- **한도**: 보드당 멤버 20명, 동시 접속 10명, 문서 크기 10MB. 넘으면 서버가 거절하고 화면에 이유를 쓴다.
- **참여자 색**: 시스템 색 8개를 접속 순서로 돌려 쓴다.

## 6. 수용 기준 (Acceptance Criteria)

### AC-1 — 혼자 쓰는 보드는 로그인 없이 그대로 (⛔ 폐기 2026-09-29 — [[FEAT-onboarding-routes]] D5, 로그인 필수)
- **Given** 로그인한 적 없는 기기에서 앱을 연다
- **When** 보드를 만들고 메모를 쓰고 새로고침한다
- **Then** 로그인 화면이 한 번도 안 뜬다. 메모가 그대로 있다. 네트워크 요청이 Ktor·Hocuspocus로 한 건도 안 나간다.

### AC-2 — Dexie v6 보드 자동 이전
- **Given** Dexie v6에 보드 3개, 메모 50장, 연결선 10개, 휴지통 5건이 있다
- **When** 새 버전을 처음 연다
- **Then** 보드마다 Yjs 문서가 생기고 메모·연결선·좌표·제목·색·손글씨 레이어가 같다. 휴지통 5건은 Dexie에 그대로 남는다. `settings`도 그대로다. 원본 `notes`·`boards`·`connections` 테이블은 지우지 않는다.

### AC-3 — 이전 실패 격리
- **Given** 보드 하나의 변환이 예외를 던진다
- **When** 첫 실행 이전이 돈다
- **Then** 나머지 보드는 정상 변환되어 열린다. 실패한 보드는 "아직 옮기지 못했어요" 표시와 함께 목록에 남고 다음 실행에 다시 시도한다. 3번 실패하면 내보내기 버튼을 보여준다.

### AC-4 — 공유 시작과 로그인
- **Given** 로그인 안 한 상태에서 혼자 쓰던 보드를 보고 있다
- **When** 우상단 공유 아이콘을 누르고 Google 버튼을 누른다
- **Then** Google 동의 뒤 팝오버가 링크 복사 줄과 내 이름으로 바뀐다. 이 보드만 서버에 올라간다. 다른 보드는 올라가지 않는다. 클릭 수는 3번 이내다.

### AC-5 — 초대 링크로 들어오기
- **Given** 편집자가 될 사람이 초대 링크를 처음 연다
- **When** 카드에서 Google 버튼을 눌러 로그인한다
- **Then** 카드에 초대한 사람 이름과 보드 이름이 보인다. 로그인 후 보드가 열리고 편집자로 멤버 목록에 이름이 추가된다. 소유자 화면의 아바타 줄에 새 사람이 5초 안에 나타난다.

### AC-6 — 링크 재발급
- **Given** 편집자 B가 옛 링크를 갖고 있다
- **When** 소유자가 멤버 메뉴에서 링크를 재발급한다
- **Then** 옛 링크를 열면 "만료된 초대예요"가 보이고 로그인 버튼이 없다. 이미 들어와 있던 B는 계속 편집할 수 있다. 재발급은 멤버를 내보내지 않는다.

### AC-7 — 커서와 드래그 스트리밍
- **Given** 소유자와 편집자가 같은 보드에 접속해 있다
- **When** 편집자가 메모를 끌고 있다
- **Then** 소유자 화면에 편집자 색의 커서·이름표·끌리는 메모의 잔상이 보인다. 끄는 동안 Yjs 문서에는 쓰기가 0건이다. 놓는 순간 1건이 써진다.

### AC-8 — 같은 메모를 동시에 놓기
- **Given** 두 사람이 같은 메모를 각자 끌고 있다
- **When** 두 사람이 1초 안에 각각 다른 자리에 놓는다
- **Then** 두 화면의 메모 좌표가 1초 안에 같아진다. 메모가 사라지거나 둘로 늘지 않는다. 어느 쪽 좌표가 이기는지는 Yjs가 정하고 사용자에게 묻지 않는다.

### AC-9 — 선택 테두리
- **Given** 편집자가 메모 2장을 선택했다
- **When** 소유자가 그 보드를 본다
- **Then** 그 2장에 편집자 색 1.5px 테두리가 보인다. 소유자가 같은 메모를 선택해도 편집이 막히지 않는다. 잠금은 없다.

### AC-10 — 오프라인 편집 후 복귀
- **Given** 편집자가 공유 보드를 연 채 네트워크가 끊긴다
- **When** 메모 3장을 옮기고 1장을 새로 쓴 뒤 네트워크가 돌아온다
- **Then** 끊긴 동안 우상단에 "오프라인" 표시가 있고 편집은 막히지 않는다. 복귀 10초 안에 4건이 다른 참여자 화면에 반영된다. 아무것도 사라지지 않는다.

### AC-11 — 보드 토큰 만료
- **Given** 편집 중 보드 토큰 1시간이 지났다
- **When** Hocuspocus가 재연결을 요구한다
- **Then** 클라이언트가 Ktor에서 새 보드 토큰을 받아 재연결한다. 사용자는 아무것도 누르지 않는다. 그 사이 쓴 편집은 y-indexeddb에 남았다가 재연결 뒤 올라간다.

### AC-12 — 리프레시 토큰 만료
- **Given** 30일 넘게 앱을 안 열어 리프레시 JWT가 만료됐다
- **When** 공유 보드를 연다
- **Then** 보드를 흐리게 깔고 로그인 카드가 뜬다. 로그인하면 같은 자리로 돌아온다. 로컬 사본은 로그인 전에 지워지지 않는다.

### AC-13 — 공유 해제
- **Given** 소유자와 편집자 2명이 접속해 있다
- **When** 소유자가 멤버 메뉴에서 공유를 해제한다
- **Then** 편집자 2명의 화면에 "공유가 끝난 보드예요"가 한 번 뜨고 보드 목록에서 사라진다. 그 기기의 y-indexeddb 문서와 Dexie 파생 행이 0건이다. 소유자 기기에는 보드가 남고 혼자 쓰는 보드로 돌아간다. 서버의 문서 행은 지운다.

### AC-14 — 오프라인 편집자를 내보내기
- **Given** 편집자 B가 오프라인일 때 소유자가 B를 내보냈다
- **When** B가 온라인이 되어 그 보드를 연다
- **Then** 서버가 연결을 거절한다. B 기기의 사본이 지워지고 알림이 한 번 뜬다. B가 오프라인 동안 쓴 편집은 버려진다. 다른 보드는 영향이 없다.

### AC-15 — 한도
- **Given** 보드에 멤버 20명이 있다
- **When** 21번째 사람이 초대 링크로 로그인한다
- **Then** "이 보드는 자리가 다 찼어요"가 보이고 멤버가 늘지 않는다.

### AC-16 — MCP 브리지 무영향
- **Given** 브리지가 웹 탭에 붙어 있다
- **When** `boards.create`·`notes.create`·`notes.delete`를 부른다
- **Then** 응답 형식이 지금과 같다. 공유 보드면 다른 참여자에게도 1초 안에 보인다.

### AC-17 — 다른 기기에서 내 공유 보드 열기
- **Given** 노트북에서 공유한 보드 2개와 혼자 쓰는 보드 3개가 있다
- **When** 데스크톱에서 같은 Google 계정으로 로그인한다
- **Then** 데스크톱 보드 목록에 공유 보드 2개가 10초 안에 나타나고 열린다. 혼자 쓰는 보드 3개는 나타나지 않는다. 역할은 노트북과 같다.

## 7. 경계 조건

- **입력**: 보드 이름 80자, 메모 수 보드당 1,000장까지 성능 보장. 문서 10MB를 넘으면 Hocuspocus가 쓰기를 거절하고 클라이언트가 "보드가 너무 커요"를 보여준다.
- **동시성**: 같은 키를 두 사람이 쓰면 Yjs의 마지막 쓰기가 이긴다. 같은 메모를 한쪽이 지우고 한쪽이 옮기면 삭제가 이긴다. 옮긴 사람의 화면에서도 메모가 사라진다.
- **오프라인**: 혼자 쓰는 보드는 네트워크와 무관하다. 공유 보드는 y-indexeddb 덕에 편집이 이어지고 복귀 때 병합된다. 오프라인 상태 표시는 [[FEAT-signals]]의 `useOnlineStatus`를 쓴다.
- **토큰 만료**: 액세스 JWT가 만료되면 리프레시로 조용히 갱신한다. 리프레시까지 만료되면 로그인 카드다. 보드 토큰 만료는 AC-11.
- **공유 해제 중 편집**: 해제 신호와 편집이 같은 순간 겹치면 편집을 버린다. 서버는 해제 뒤 도착한 업데이트를 무시한다.
- **이전 실패**: 보드 단위로 격리한다. AC-3. 변환 중 브라우저를 닫으면 다음 실행에 처음부터 다시 한다. 변환은 멱등이다.
- **여러 탭**: 같은 기기의 탭 2개가 같은 보드를 열면 Yjs 업데이트를 BroadcastChannel로 주고받는다. 기존 [[FEAT-memo-multitab-sync]]의 카드 단위 충돌 처리는 사라진다.
- **첨부**: 공유 보드의 첨부는 Ktor `POST /boards/{id}/files`로 올리고 볼륨 `/data/files/{boardId}/{fileId}`에 둔다. 파일 1개 20MB, 보드당 500MB. 업로드 전이거나 실패한 첨부는 다른 참여자에게 "올리는 중" 자리표시자로 보인다. 공유 해제 시 그 보드의 파일 디렉터리를 지운다. 혼자 쓰는 보드의 첨부는 지금처럼 OPFS에만 있다.
- **실패 모드**: Hocuspocus가 죽으면 편집은 이어지고 상태 표시만 바뀐다. Ktor가 죽으면 새 로그인·초대·해제만 안 된다. Postgres가 죽으면 Hocuspocus가 스냅샷을 못 쓰므로 연결을 거절한다.

## 8. 상태 모델

보드의 공유 상태는 3개다.

| 상태 | 뜻 |
|---|---|
| local | 기기에만 있다. 서버에 행이 없다. 기본값 |
| shared | 서버에 문서가 있고 멤버가 1명 이상이다 |
| revoked | 소유자가 해제했다. 서버 행은 지워졌다. 편집자 기기에서는 사본 삭제 대기 상태 |

합법 전이:
- local → shared: 소유자가 로그인하고 공유를 켠다.
- shared → revoked: 소유자가 해제한다.
- revoked → local: 소유자 기기에서만. 편집자 기기에서는 revoked → 삭제.

불가능한 조합:
- local인데 멤버가 있다.
- shared인데 소유자가 없다.
- 편집자가 해제한다. 편집자는 나가기만 할 수 있다.
- revoked인데 서버에 문서 행이 남아 있다.

멤버 역할은 소유자·편집자 둘이고 보드당 소유자는 정확히 1명이다. 소유자 이전은 없다.

## 14. 구현 메모

- Yjs 문서 구조: `Y.Map notes` (id → Y.Map 필드), `Y.Map connections`, `Y.Map meta` (name, parentBoardId). 메모 본문은 `Y.Text`가 아니라 문자열 필드로 시작한다. 문자 단위 병합은 Milkdown 연동이 필요해 이번엔 뺀다. 같은 메모를 둘이 동시에 타이핑하면 마지막 쓰기가 이긴다.
- Dexie 파생 인덱스로 남는 테이블: `embeddings`, `trash`, `trashConnections`, `settings`. `notes`·`boards`·`connections`는 한 버전 뒤 v8에서 지운다. v7은 스키마 변경 없이 이전 완료 플래그만 `settings`에 둔다.
- 이전 코드 위치: `web/src/state/storage.ts`의 `init()`이 OPFS purge 뒤에 보드 단위로 돈다. 실패 카운트는 `settings.migrationFailures[boardId]`.
- 스토어: `web/src/state/workspace.ts`의 액션 시그니처는 유지한다. `cardPersist.ts`가 Dexie 대신 Yjs 트랜잭션을 연다. `moveCard`는 Awareness, 드롭 시 `commitMove`가 문서에 쓴다.
- 멀티탭: `web/src/state/db/liveSync.ts` 419줄을 Yjs update 브로드캐스트 30줄 안팎으로 바꾼다. `isCardConflicted`·`resolveConflict`는 지운다.
- MCP 브리지: `mcp/src/bridge.ts`는 WebSocket으로 웹 탭의 스토어 액션을 부른다. 스토어 시그니처가 유지되므로 브리지 코드는 안 바뀐다.
- 서버 테이블: `users(id, google_sub, name, avatar)`, `boards(id, owner_id, name, state, created_at)`, `board_members(board_id, user_id, role)`, `invites(board_id, token_hash, created_at)`, `documents(board_id, snapshot bytea, updated_at)`.
- Ktor 엔드포인트: `POST /auth/google`, `POST /auth/refresh`, `POST /boards/:id/share`, `DELETE /boards/:id/share`, `POST /boards/:id/invite`, `POST /invites/accept` (본문 `{"token"}` — 토큰이 접속 로그에 남지 않게), `DELETE /boards/:id/members/:userId`, `POST /boards/:id/token`.
