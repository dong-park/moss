# FEAT-onboarding-routes · 로그인 온보딩과 보드마다 UUID 주소

> moss는 로그인해야 쓴다. 처음 온 사람은 로그인 온보딩을 거친다. 기본 보드를 포함한 모든 보드가 UUID 주소를 가진다. 새로고침해도, 링크를 붙여 넣어도 같은 보드가 열린다.

**Status**: spec 작성 (2026-09-29, 로그인 필수·시스템 보드 UUID 반영)
**Estimated**: L
**계획**: [[FEAT-onboarding-routes.plan]] — 노드 6개
**Blueprint**: (미등록)

## 1. 목표

moss를 쓰는 사람은 노션처럼 보드 주소를 복사해 다른 탭이나 동료에게 넘기고 싶다. 지금은 주소가 `/` 하나라서 새로고침하면 늘 기본 보드로 돌아간다. 처음 온 사람은 빈 캔버스를 보고 무엇을 할지 모른다. 공동 편집이 들어오면서 계정이 기본이 됐으니, 로그인 없는 사용자를 따로 챙기는 비용을 없앤다.

## 2. 범위

### 포함
- 로그인 전에는 로그인 온보딩 화면만 보인다
- 시스템 보드를 UUID id로 옮기는 데이터 이전
- 보드·서브 캔버스마다 `/b/[boardId]` 주소
- 뒤로 가기·앞으로 가기로 보드 이동
- `/` 진입 시 로그인 안 했으면 로그인 온보딩, 했으면 마지막 보드로 이동
- 없는 보드, 권한 없는 공유 보드 안내
- 초대 수락 뒤 보드 주소로 이동

### 제외
- 메모 하나하나의 주소 — 11절
- 보드 목록 화면 — 11절

## 3. 현재 상태

- 라우트는 `/`와 `/j/[token]` 두 개다.
- 보고 있는 보드는 `useWorkspace.currentBoardId`에만 있다.
- 기본 보드 id는 고정값 `"system"`이다.
- 새 보드 id는 `b-${Date.now().toString(36)}-${counter}` 형식이다. UUID가 아니다.
- 보드 전환은 `setCurrentBoard(id)` 하나로 모인다.

| D5-2 | 로그인 전에 만든 로컬 데이터는 처음 로그인한 계정에 묶는다. 이 브라우저에 다른 계정으로 로그인하면 "다른 계정의 보드가 이 기기에 있어요" 안내 뒤 로그아웃 또는 계속을 고르게 한다 | 로컬 저장소가 계정별로 나뉘어 있지 않다. 계정별 분리는 11절 |
| D5-3 | 한 번 로그인한 기기는 오프라인에서 세션이 만료돼도 계속 쓴다. 온라인이 되면 로그인 카드가 뜬다 | 오프라인 편집을 막으면 로컬 우선 앱의 장점이 사라진다 |
| D6 | 공유 보드도 `/b/[id]`. 로컬에 없는 id면 로그인 상태에서 서버 멤버십을 확인해 연다 | 공유 보드 주소를 받은 멤버가 다른 기기에서 바로 연다 |
| D7 | 초대는 계속 `/j/[token]`. 수락 뒤 `/b/[id]`로 replace | 토큰이 주소창·방문 기록에 남지 않는다 |
| D8 | 원본은 URL이다. 기존 `setCurrentBoard` 호출부는 `router.push`로 바꾸고, `/b/[id]` 페이지가 URL을 보고 `setCurrentBoard`를 부른다 | 원본이 둘이면 뒤로 가기에서 어긋난다 |

## 5. 수용 기준

### AC-1 — 새로고침 유지
- **Given** 보드 A를 `/b/A`로 보고 있다
- **When** 새로고침한다
- **Then** 보드 A가 다시 열린다. viewport도 이전 위치다.

### AC-2 — 주소 붙여 넣기
- **Given** 같은 브라우저 다른 탭에 `/b/A`를 붙여 넣는다
- **Then** 보드 A가 열린다.

### AC-3 — 서브 캔버스와 뒤로 가기
- **Given** 보드 A에서 함 카드를 열어 서브 보드 S로 들어갔다
- **When** 주소가 `/b/S`로 바뀐 걸 확인하고 브라우저 뒤로 가기를 누른다
- **Then** `/b/A`로 돌아가고 보드 A가 보인다. 앞으로 가기는 다시 S다.

### AC-4 — 로그인 온보딩
- **Given** 로그인하지 않았다
- **When** `/` 또는 `/b/아무id`를 연다
- **Then** 로그인 온보딩 화면이 보인다. 캔버스와 Dock은 보이지 않는다. 로그인하면 원래 열려던 주소로 돌아간다.

### AC-5 — 첫 보드 고르기
- **Given** 방금 로그인했고 보드가 하나도 없다
- **When** "예제로 시작"을 누른다
- **Then** 예제 메모 3장이 든 새 보드가 UUID id로 만들어지고 `/b/<uuid>`로 이동한다.
- **When** 대신 "빈 보드로 시작"을 누른다
- **Then** 빈 보드가 만들어지고 그 주소로 이동한다.

### AC-6 — 재방문
- **Given** 로그인했고 마지막으로 연 보드가 A다
- **When** `/`를 연다
- **Then** `/b/A`로 replace된다. 뒤로 가기를 눌러도 `/`로 돌아가지 않는다.

### AC-7 — 기존 사용자와 시스템 보드 이전
- **Given** 이 기능 전부터 로그인 없이 쓰던 사용자다. 시스템 보드에 메모가 있다
- **When** `/`를 열고 로그인한다
- **Then** 첫 보드 고르기 없이 마지막 보드로 간다. 시스템 보드는 `/b/<uuid>` 주소를 가진다. 이전 전후 메모 수와 내용이 같다.
- **When** 이전 중 브라우저를 닫고 다시 연다
- **Then** 이전이 처음부터 다시 돌고 메모가 중복되지 않는다.

### AC-8 — 없는 보드
- **Given** 지워졌거나 오타 난 id다
- **When** `/b/없는id`를 연다
- **Then** "찾을 수 없는 보드예요" 카드와 "마지막 보드로" 버튼이 보인다. 빈 보드가 새로 생기지 않는다.

### AC-9 — 내 공유 보드를 다른 기기에서
- **Given** 로그인했고 공유 보드 P의 멤버다. 이 기기에는 P가 없다
- **When** `/b/P`를 연다
- **Then** 서버에서 P를 받아 연다.

### AC-10 — 권한 없는 공유 보드
- **Given** P의 멤버가 아니거나 로그인하지 않았다
- **When** `/b/P`를 연다
- **Then** "이 보드를 볼 수 없어요" 카드가 보인다. 로그인하지 않았으면 로그인 버튼이 함께 보인다. 보드 존재 여부는 드러내지 않는다.

### AC-11 — 초대 수락 뒤 주소
- **When** `/j/[token]`에서 초대를 수락한다
- **Then** `/b/[boardId]`로 replace된다. 뒤로 가기에 토큰 주소가 남지 않는다.

### AC-12 — 이전 중 진입
- **Given** Dexie→Yjs 이전이 진행 중이다
- **When** `/b/A`를 연다
- **Then** 이전이 끝난 뒤 A가 열린다. 이전 중에는 기존 오버레이만 보인다.

### AC-15 — 다른 계정으로 로그인
- **Given** 계정 X로 쓰던 브라우저다
- **When** 로그아웃하고 계정 Y로 로그인한다
- **Then** "다른 계정의 보드가 이 기기에 있어요" 안내가 뜬다. X의 보드는 자동으로 Y에 올라가지 않는다.

### AC-13 — 오프라인
- **Given** 오프라인이다. 이 기기에서 전에 로그인한 적이 있다
- **When** 로컬에 있는 보드 주소를 연다
- **Then** 네트워크 없이 열린다. 로컬에 없는 공유 보드면 AC-8 카드 대신 "연결되면 다시 시도할게요"가 보인다.

### AC-14 — 회귀
- 기존 vitest가 전부 통과한다. "로그인 없이 혼자 쓰기"를 검사하던 테스트는 로그인 상태를 주입하도록 고친다.
- MCP 브리지와 시스템 보드 토글 단축키가 동작한다. 단축키도 주소를 바꾼다.

## 6. 엣지 케이스

- **같은 보드 주소로 push**: 이미 그 보드면 history를 쌓지 않는다.
- **보드 삭제 후 뒤로 가기**: 지운 보드 주소로 돌아오면 AC-8 카드다. 휴지통에서 복원하면 같은 주소로 다시 열린다.
- **공유 해제 후**: 편집자가 해제된 보드 주소를 열면 AC-10 카드다.
- **여러 탭**: 탭마다 주소가 독립이다. 한 탭에서 보드를 바꿔도 다른 탭은 따라가지 않는다.

## 7. 화면

- 온보딩은 캔버스 배경 위 가운데 카드 하나다. 제목 한 줄, 설명 한 줄, 버튼 두 개.

## 12. 구현 메모

- 라우트: `app/b/[boardId]/page.tsx`가 지금 `app/page.tsx`의 워크스페이스를 그대로 렌더한다. 워크스페이스 본문은 컴포넌트로 뽑는다. `app/page.tsx`는 갈림길만 남긴다.
- 동기화: `/b/[boardId]` 페이지의 effect가 `params.boardId`로 `setCurrentBoard`를 부른다. `setCurrentBoard`를 부르던 곳은 `router.push(`/b/${id}`)`로 바꾼다. 호출부는 `grep setCurrentBoard`로 찾는다. createBoard·toggleSystemBoard·함 카드 진입·Breadcrumb·초대 수락이 들어간다.
- `createBoard`의 `setCurrentBoard(id)` 호출은 빼고 id만 돌려준다. 호출부가 push한다.
- 로그인 게이트: 지금 `AuthBootstrap`이 세션을 복원한다. 워크스페이스 레이아웃이 세션 없으면 온보딩을 렌더하고 원래 주소를 `?next=`로 넘긴다.
- 시스템 보드 이전: `SYSTEM_BOARD_ID` 참조 13개 파일, `boardId === null` 분기 15곳을 고친다. `storageBoardId()`의 null 매핑을 없앤다. 이전은 기존 Dexie→Yjs 이전 뒤에 이어 붙이고 `settings.systemBoardMigratedAt`으로 한 번만 돈다. Yjs 문서 키도 null 키에서 새 UUID 키로 옮긴다.
- MCP 브리지(`mossBridge.ts`)와 내보내기·가져오기가 시스템 보드를 id로 찾도록 바꾼다. 옛 번들을 가져올 때 boardId=null은 시스템 보드 UUID로 바꾼다.
- 첫 보드 고르기(n4): `/`(RootBoardRedirect)에 `needsFirstBoard(boards, cards)` 판정을 둔다. 사용자 보드가 하나도 없고 시스템 보드에 사용자가 만든 카드가 없으면 `FirstBoardChooser`를 띄운다. "예제로 시작"은 `createExampleBoard()`(예제 메모 3장 든 UUID 보드), "빈 보드로 시작"은 기존 `createBoard()`를 부른다. 둘 다 `navigateToBoard`가 `/b/<uuid>`로 이동시킨다.
- [[FEAT-collab-auth]] AC-1을 폐기로 표시한다.

### 가정하고 진행한 것
- 시스템 보드 id는 랜덤이 아니라 고정 UUID `00000000-0000-4000-8000-000000000001`이다. 기기 로컬 전용이라 겹쳐도 문제없고, 초기값과 이전값이 어긋날 분기를 없앤다. `SYSTEM_BOARD_ID` 상수는 이 값으로 남긴다. D3의 "상수 삭제"를 뒤집었다.
- 고정 UUID라서 시스템 보드는 공유할 수 없다. 공유 버튼을 `isSystem` 보드에서 숨긴다. 공유하면 서버 행이 사용자끼리 겹친다.
- D5-2 "계속"은 안내만 닫는다. `ownerUserId`는 바꾸지 않는다. 다른 계정도 로컬 보드를 계속 본다.
- 첫 로그인 계정을 로컬 데이터 유무와 상관없이 owner로 기록한다.
- 온보딩 문구와 기능 3개는 runner가 i18n에 임의로 썼다.
- 원래부터 red인 `Canvas.virtualization` 테스트 1개와 lint 오류 3개는 범위 밖이라 두었다.
- n3: 스토어는 `setCurrentBoard` 대신 `navigateToBoard`로 라우터 sink에 push를 요청한다. 라우터가 없는 테스트 환경에서는 `setCurrentBoard`로 폴백해 유닛 테스트가 URL 없이도 전환 의미를 유지한다. `bootstrapComplete` 플래그로 이전 완료 뒤에만 URL의 보드를 연다.
- n3: "마지막 연 보드"는 `boards`를 `lastOpenedAt` 내림차순으로 본 첫 행이다. 시스템 보드도 평범한 행이 된 뒤로는 방문 시각을 갱신한다.
