# FEAT-sticky-redesign · 겉은 포스트잇, 안은 문서

> 캔버스에서는 포스트잇처럼 훑어보고, 누르면 디지털 문서로 들어간다. 카드 종류를 메모 하나로 줄이고, 메모판·파일함·하단 독으로 정리한다.

## 1. 목표 (Job Statement)

노션 DB를 옆에 두고 포스트잇으로 프로젝트를 다루던 사람이 moss에서 같은 방식으로 일하고 싶다. 캔버스에서는 노란 메모를 메모판에 붙여 한눈에 보고, 메모를 누르면 글·이미지·링크·녹음·파일이 한 문서에 담긴 창이 열린다. 카드 종류가 여러 개라 무엇을 골라야 할지 망설이던 순간을 없앤다.

## 2. 범위

### 포함 (in-scope)

- **메모는 한 종류다.** 이미지·링크·녹음·파일은 메모 안의 블록이다.
- 캔버스에 이미지나 URL을 붙여넣거나 떨어뜨리면 블록 하나가 든 메모가 생긴다.
- 파일을 캔버스에 떨어뜨리면 파일 블록 하나가 든 메모가 생긴다.
- 메모 앞면은 메모 창과 **같은 배치**를 위에서부터 잘라 보여준다. 앞면에서만 블록을 숨기거나 줄이지 않는다(펜 좌표 1:1 유지).
- 이미지는 앞면·창 모두 본문 칸 폭에 맞춘다. 첫 블록이 이미지면 잘린 앞면 윗부분이 곧 그 이미지다.
- 녹음·파일·링크 블록은 앞면·창 모두 같은 고정 높이의 한 줄 막대다. 창에서는 재생·열기 버튼이 보이고, 앞면에서는 버튼 없이 흐리게 보인다.
- 앞면 아래쪽에 종류별 개수 배지를 겹쳐 올린다. 배지는 본문 배치에 영향을 주지 않는다.
- 메모 창은 기존 확대 창을 넓혀 쓴다. 글과 네 가지 블록을 한 문서에서 편집한다.
- 메모 창에 블록 추가 메뉴를 둔다. 항목은 이미지, 링크, 녹음, 파일 네 개다.
- **메모판**은 캔버스 위에 그리는 이름 붙은 틀이다.
- 메모를 메모판 안으로 끌어 놓으면 그 판에 속한다. 판을 옮기면 속한 메모도 같이 옮겨진다.
- 한 캔버스에 메모판을 여러 개 둘 수 있다.
- 파일함은 기존 서브 캔버스 함을 그대로 쓴다. 이름만 파일함으로 바꾼다. 들어가면 브레드크럼이 보인다.
- UI에서 보드라는 말을 프로젝트로 바꾼다. 상단 프로젝트 선택 드롭다운은 그대로 둔다.
- 시스템 보드 "머무는 생각"은 이름과 동작을 그대로 둔다.
- 왼쪽 사이드바를 없애고 화면 아래 가운데에 독을 둔다.
- 독 순서는 메모판, 메모, 파일함, 구분선, 펜 토글, 시그널스다.
- 독 아이콘에 마우스를 올리면 맥 독처럼 커지고 이름표가 뜬다.
- 독에서 캔버스로 한 번 끌면 메모판·메모·파일함이 생긴다.
- 독 뒤에 메모가 가려지면 독만 옅게 보인다. 독은 자동으로 숨지 않는다.
- **옛 카드는 이관하지 않는다.** DB v5로 올라갈 때 기존 데이터(메모·프로젝트·연결·임베딩·첨부)를 비우고 빈 상태로 시작한다(2단계 리뷰 후 사용자 결정 2026-09-13).
- 줌 바는 오른쪽 아래에 그대로 둔다. 시그널스 패널도 그대로 두고 여는 버튼만 독으로 옮긴다.

### 제외 (비목표)

- 메모판 안에 메모판을 넣지 않는다.
- 메모판을 파일함 안으로 옮기지 않는다. 메모만 옮긴다.
- 녹음·마인드맵을 단독으로 만드는 도구를 되살리지 않는다.
- 메모 앞면에서 녹음을 재생하거나 파일·링크를 열지 않는다.
- 선·열·댓글·더보기·휴지통 버튼을 독으로 옮기지 않는다. 지금도 동작이 없는 버튼이다.
- 댓글 카드 생성 경로를 만들지 않는다. 저장 구조에만 남긴다.
- 코드 식별자에서 board를 project로 바꾸지 않는다. 바뀌는 것은 화면 글자뿐이다.
- 프로젝트 선택 드롭다운의 트리 표시는 하지 않는다. [[FEAT-subcanvas]]의 후속을 따른다.
- 메모판 소속을 AI 연결이나 시그널스 판단에 쓰지 않는다. [[FEAT-signals]] 범위다.

## 3. 수용 기준 (Acceptance Criteria)

### AC-1 — 사이드바가 사라지고 독이 보인다
- **Given** 앱을 연다.
- **When** 첫 화면이 그려진다.
- **Then** 사이드바 요소가 DOM에 없다.
- **And** 캔버스가 화면 왼쪽 끝부터 시작한다.
- **And** 화면 아래 가운데에 독이 하나 보인다. 버튼 5개와 구분선 1개가 순서대로 있다.

### AC-2 — 독 확대
- **Given** 독 아이콘이 기본 크기 40px로 보인다.
- **When** 메모 아이콘 위에 마우스를 올린다.
- **Then** 그 아이콘이 72px로 커지고 "메모" 이름표가 뜬다.
- **And** 이웃 아이콘은 거리에 따라 40px과 72px 사이로 커진다.
- **When** 마우스가 독을 벗어난다.
- **Then** 모든 아이콘이 200ms 안에 40px로 돌아온다.

### AC-3 — 독에서 끌어 만들기
- **Given** 프로젝트 캔버스가 열려 있다.
- **When** 메모 아이콘을 눌러 캔버스 위에 끌어 놓는다.
- **Then** 놓은 자리에 빈 메모가 1개 생긴다. 저장소에 text 종류 행이 1개 늘어난다.
- **And** 끄는 동안 독은 확대 상태를 유지한다.
- **When** 메모판 아이콘을 끌어 놓는다.
- **Then** 이름이 "새 메모판"인 틀이 생긴다.
- **When** 파일함 아이콘을 끌어 놓는다.
- **Then** 기존 함 생성과 똑같이 파일함 카드와 빈 하위 캔버스가 생긴다.
- **When** 끌기를 독 위에서 놓거나 Esc를 누른다.
- **Then** 아무것도 생기지 않는다.

### AC-4 — 독의 펜과 시그널스
- **When** 펜 버튼을 누른다.
- **Then** 펜 모드가 켜지고 버튼이 눌린 상태로 보인다. 다시 누르면 꺼진다.
- **When** 시그널스 버튼을 누른다.
- **Then** 오른쪽 420px 시그널스 패널이 열린다.

### AC-5 — 가려진 메모가 있으면 독이 옅어진다
- **Given** 메모 하나가 독의 화면 영역과 겹친다.
- **Then** 독의 불투명도가 0.6이 된다.
- **When** 독에 마우스를 올린다.
- **Then** 불투명도가 1로 돌아온다.
- **Given** 겹치는 메모가 없다.
- **Then** 독의 불투명도는 1이다.

### AC-6 — 이미지 붙여넣기
- **Given** 캔버스를 보고 있고 입력칸에 커서가 없다.
- **When** 클립보드의 PNG 이미지를 붙여넣는다.
- **Then** 화면 가운데에 메모 1개가 생긴다.
- **And** 저장소에 text 종류 행이 1개 늘고, 본문은 OPFS 이미지 블록 하나다.
- **And** image 종류 행은 늘지 않는다.

### AC-7 — URL 붙여넣기와 파일 드롭
- **When** URL 한 줄만 붙여넣는다.
- **Then** 링크 블록 하나가 든 text 메모가 생긴다. link 종류 행은 늘지 않는다.
- **When** PDF 파일을 캔버스에 떨어뜨린다.
- **Then** 떨어뜨린 자리에 파일 블록 하나가 든 text 메모가 생긴다.
- **When** 이미지 파일을 떨어뜨린다.
- **Then** 이미지 블록 하나가 든 text 메모가 생긴다.

### AC-8 — 메모 앞면
- **Given** 첫 블록이 이미지이고, 아래에 녹음 2개와 링크 1개가 있는 메모다.
- **Then** 앞면 위쪽에 이미지가 본문 칸 폭에 맞춰 보인다.
- **And** 앞면 아래쪽에 녹음 2, 링크 1 배지가 겹쳐 보인다. 파일 배지는 없다.
- **And** 앞면에 재생 버튼과 링크 열기 요소가 없다. 블록 막대는 흐린 한 줄로 보인다.
- **And** 창에서 "본문" 글자 위에 그은 펜 선이 앞면에서도 같은 글자 위에 있다(블록 각각의 앞면 높이 = 창 높이).
- **When** 배지나 앞면 이미지를 누른다.
- **Then** 메모 창이 열린다.

### AC-9 — 메모 창에서 블록 추가
- **Given** 메모 창이 열려 있다.
- **When** 블록 추가 메뉴를 연다.
- **Then** 이미지, 링크, 녹음, 파일 네 항목이 보인다.
- **When** 링크를 골라 URL을 넣는다.
- **Then** 커서 자리에 링크 블록이 들어가고, 창을 닫으면 앞면 링크 배지가 1 늘어난다.
- **When** 녹음을 골라 녹음하고 멈춘다.
- **Then** 녹음 블록이 들어가고 창 안에서 재생된다.
- **When** 새로고침한다.
- **Then** 네 종류 블록이 모두 그대로 보인다.

### AC-10 — 메모판 소속
- **Given** 메모판 A와 판 밖의 메모 M이 있다.
- **When** M의 중심점이 A 안에 들어가게 끌어 놓는다.
- **Then** M은 A에 속한다. 새로고침 뒤에도 유지된다.
- **When** M의 중심점이 A 밖으로 나가게 끌어 놓는다.
- **Then** M은 어느 판에도 속하지 않는다.
- **When** M의 절반이 A 경계에 걸쳤고 중심점은 안에 있다.
- **Then** M은 A에 속한다.

### AC-11 — 메모판을 옮기면 메모도 따라온다
- **Given** 메모판 A에 메모 3개가 속해 있다.
- **When** A를 오른쪽으로 200px 옮긴다.
- **Then** 메모 3개도 각각 오른쪽으로 200px 옮겨진다.
- **And** A에 속하지 않은 메모는 제자리에 있다.
- **When** 새로고침한다.
- **Then** 옮긴 위치가 그대로다.

### AC-12 — 메모판 중첩 불가
- **Given** 메모판 A와 B가 있다.
- **When** B를 A 안에 끌어 놓는다.
- **Then** B는 A에 속하지 않는다. A를 옮겨도 B는 제자리다.

### AC-13 — 파일함과 프로젝트 명칭
- **When** 파일함 카드를 더블클릭한다.
- **Then** 하위 캔버스로 들어가고 브레드크럼이 보인다. 동작은 [[FEAT-subcanvas]] AC와 같다.
- **Then** 화면 어디에도 "보드"라는 글자가 없다. 그 자리는 "프로젝트"다.
- **And** "머무는 생각" 이름은 그대로다.

### AC-14 — 새 DB로 시작
- **Given** v4 DB에 image, link, audio, file, mindmap, text 카드와 사용자 프로젝트, OPFS 첨부가 있다.
- **When** 새 버전으로 앱을 연다.
- **Then** DB 버전이 5이고 notes·boards·connections·embeddings가 비어 있다. 시스템 보드 "머무는 생각"은 빈 상태로 보인다.
- **And** OPFS 첨부 디렉터리가 비어 있다.
- **And** 한 번 v5로 연 뒤 새로 만든 메모는 다음 실행에서 지워지지 않는다.

## 4. 경계 조건

### 입력 범위

- 이미지 블록 한도는 [[FEAT-memo-image-paste]]와 같다. 10MB를 넘거나 지원 안 하는 형식이면 토스트로 알리고 무시한다.
- 파일 블록과 녹음 블록은 한 개당 50MB까지다. 넘으면 토스트로 알리고 무시한다.
- 여러 파일을 한 번에 떨어뜨리면 파일마다 메모를 하나씩 만든다. 놓은 자리에서 24px씩 비켜 쌓는다.
- 한 번에 떨어뜨리는 파일은 20개까지다. 나머지는 토스트로 알리고 버린다.
- 메모판 이름은 1자에서 40자다. 빈 이름으로 저장하면 "새 메모판"으로 돌린다.
- 메모판 최소 크기는 240×160px이다.
- 링크 블록 제목이 비면 URL을 제목으로 쓴다.
- 입력칸에 커서가 있으면 캔버스 붙여넣기는 동작하지 않는다. 기존 규칙과 같다.

### 소속 판정

- 소속은 메모를 끌어 놓은 순간, 판을 끌어 놓은 순간, 판 크기를 바꾼 순간에만 다시 정한다.
- 기준은 메모 중심점이다. 경계선 위의 점은 안으로 친다.
- 두 판이 겹치고 중심점이 둘 다에 들면 나중에 만든 판에 속한다.
- 판을 옮겨 놓았을 때 새로 판 안에 들어온 메모도 그 판에 속하게 된다.
- 판 크기를 줄여 중심점이 밖으로 나간 메모는 소속이 풀린다.
- 파일함 카드도 메모처럼 판에 속할 수 있다.
- 메모를 파일함에 넣어 다른 캔버스로 보내면 판 소속이 풀린다.

### 동시성

- 판 이동은 판과 속한 메모 전부를 한 트랜잭션으로 저장한다. 일부만 저장되는 일은 없다.
- 판과 그 판의 메모를 함께 다중 선택해 옮기면 메모는 한 번만 옮겨진다.
- 여러 탭이 열려 있으면 [[FEAT-memo-multitab-sync]] 규칙을 따른다. 판 이동은 마지막 저장이 이긴다.
- v4→v5 초기화는 DB 버전 업그레이드 안에서 한 번만 돈다. 중간에 탭을 닫으면 Dexie가 되돌리고 다음 실행에 다시 돈다. OPFS 첨부 비우기는 업그레이드가 끝난 뒤 한 번 하고, 실패하면 다음 실행에 다시 한다.

### 실패 모드

- 첨부 파일이 OPFS에 없으면 블록은 "파일을 찾을 수 없음" 자리표시로 보인다. 본문 참조는 지우지 않는다.
- 링크 미리보기를 못 불러오면 URL만으로 링크 블록을 유지한다.
- 마이크 권한이 없으면 녹음 블록을 넣지 않고 토스트로 알린다.
- 판을 지우면 속한 메모는 제자리에 남고 소속만 풀린다. 메모를 같이 지우지 않는다.
- 시스템 보드에 파일함을 떨어뜨리는 규칙은 [[FEAT-subcanvas]]를 따른다.
- 시스템 보드에 메모·메모판을 떨어뜨리는 규칙은 기존 사이드바 드롭 토스트 동작을 따른다.

### 레이아웃

- 시그널스 패널이 열리면 독은 남은 캔버스 폭의 가운데로 옮겨간다.
- 캔버스 폭이 360px보다 좁으면 독 확대를 끈다. 모바일 레이아웃은 [[FEAT-mobile]]을 따른다.
- 사용자가 동작 줄이기를 켜 두었으면 독 확대 애니메이션을 끄고 이름표만 보여준다.
- 독은 줌 바·펜 툴바와 겹치지 않는다. 캔버스 폭이 이를 못 받치면 독이 왼쪽으로 비켜난다.

## 5. 상태 모델

### 메모의 소속

메모 하나는 판 밖이거나, 같은 캔버스의 판 하나에 속한다.

| 지금 상태 | 사건 | 다음 상태 |
|---|---|---|
| 판 밖 | 중심점이 판 P 안에 놓임 | P 소속 |
| P 소속 | 중심점이 모든 판 밖에 놓임 | 판 밖 |
| P 소속 | 중심점이 판 Q 안에 놓임 | Q 소속 |
| P 소속 | P가 지워짐 | 판 밖 |
| P 소속 | P 크기가 줄어 중심점이 밖 | 판 밖 |
| P 소속 | 파일함으로 이동 | 판 밖 |

불가능한 조합은 다음과 같다.

- 메모판이 다른 메모판에 속한다.
- 메모가 다른 캔버스에 있는 판에 속한다.
- 메모가 지워진 판을 가리킨다.
- 메모가 동시에 두 판에 속한다.

## 6. 기술 결정

- **블록은 마크다운 안에 둔다.** 메모 본문은 이미 마크다운 한 줄 문자열이다. 이미지는 이미 OPFS 이미지 문법으로 들어가 있다. 별도 JSON을 두면 카드와 창의 렌더 경로가 둘로 갈려 펜 좌표가 다시 어긋난다.
- 링크·녹음·파일 블록은 표준 마크다운 링크에 제목 표식을 붙여 구분한다. 내보내기를 해도 일반 링크로 읽혀서다.
- 녹음과 파일 바이트는 OPFS에 둔다. 기존 녹음·파일 카드와 이미지 블록이 이미 그렇게 한다.
- **메모판은 notes 테이블의 새 종류로 둔다.** 캔버스 로드·이동·삭제·undo 경로를 그대로 탈 수 있다. 새 테이블은 로드와 동기화 경로를 하나 더 만든다.
- 소속은 메모 행에 판 id로 저장한다. 매번 기하로 계산하면 판을 옮기는 도중 메모가 빠져나가는 문제가 생긴다.
- 판 id는 인덱스를 걸지 않는다. 캔버스는 이미 보드 단위로 메모 전체를 읽는다.
- 백업은 같은 행의 인덱스 없는 필드에 둔다. 행이 지워지면 백업도 같이 지워져야 해서다.
- 기존 종류 값은 타입에 남긴다. 옛 백업 파일을 가져오는 경로가 이 값을 읽는다(가져오기 시 거부 또는 무시는 n10에서 확인).
- 파일함은 새로 만들지 않고 기존 board 종류와 서브 캔버스를 쓴다. [[FEAT-subcanvas]]가 이미 끝낸 기능이다.

## 8. 비기능 요구사항

- **성능**: 메모 50개가 속한 판을 끌 때 프레임당 처리 시간이 16ms 아래다.
- **성능**: 독 확대 애니메이션은 60fps를 유지한다. 개발자 도구 성능 기록에서 긴 작업이 0개다.
- **성능**: 메모 앞면 렌더는 지금 text 카드보다 느려지지 않는다. 카드 200장 캔버스 첫 그림 시간 차이가 10% 안쪽이다.
- **접근성**: 독 버튼 5개는 Tab으로 닿고, 각각 한국어 aria-label이 있다.
- **접근성**: 키보드만으로 메모·메모판·파일함을 만들 수 있다. Enter를 누르면 화면 가운데에 생긴다.
- **접근성**: 배지는 "녹음 2개"처럼 읽힌다.
- **프라이버시**: 첨부 바이트는 기기 밖으로 나가지 않는다. 링크 미리보기 요청만 기존대로 나간다.
- **i18n**: 새 글자는 전부 i18n 키로 둔다. 보드→프로젝트 치환도 키 값만 바꾼다.
