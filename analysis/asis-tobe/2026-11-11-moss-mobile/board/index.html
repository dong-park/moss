1. 기존 할 일도, 편집할 곳이 보여야 한다

같은 할 일 카드를 한 번 탭한 상태 · 캔버스 배율 71%

현재 · 실제 기기 화면

  • 선택은 되지만 편집 진입이 없다
    제목·항목은 읽기 전용. 더블탭도 편집으로 이어지지 않았다.
  • 축소하면 버튼도 작아진다
    펼치기 버튼의 실제 터치 영역은 약 32px였다.

제안 · 아직 구현하지 않음

  • 선택한 카드에 편집·이동을 표시
    탭은 선택으로 유지한다. 「편집」을 눌러 입력을 시작한다.
  • 터치 영역은 화면 기준 44px
    캔버스가 작아져도 버튼을 누를 크기는 유지한다.
2. 키보드가 떠도, 쓰기와 끝내기가 한 화면에

같은 입력: 도크의 「메모」를 누름 · 삼성 키보드가 열린 상태

현재 · 실제 기기 화면

  • 캔버스 위 작은 제목칸에 입력
    메모 아래가 키보드에 가려진다. 입력 영역은 캔버스 배율을 따른다.
  • 완료 수단이 보이지 않는다
    도크와 줌은 키보드 뒤에 남는다. OS 뒤로가기로 키보드를 내려야 한다.

제안 · 아직 구현하지 않음

  • 새 메모는 바로 전용 편집 화면
    제목과 본문을 한 자리에서 쓴다. 키보드 높이에 맞춰 영역을 조절한다.
  • 완료 버튼은 키보드 위에 고정
    「완료」로 편집을 끝내고 원래 보드로 돌아간다.
3. 읽으러 열면 읽기, 뒤로가면 보드

같은 QA 메모 본문을 읽고 보드로 돌아가는 장면 · 본문 내용은 동일

현재 · 실제 기기 화면

  • 상세에 들어가면 키보드가 열린다
    자동 포커스로 읽을 공간이 줄고 편집 상태부터 시작한다.
  • 뒤로가기 두 번이면 Moss를 나간다
    첫 번째: 키보드 닫힘. 두 번째: 상세 대신 탭이 종료됐다.

제안 · 아직 구현하지 않음

  • 읽기는 바로, 편집은 버튼으로
    기본은 키보드 없이 본다. 「편집」을 누르면 키보드가 열린다.
  • 뒤로가기는 현재 화면부터 닫는다
    읽는 중: 상세 → 보드. 편집 중: 키보드 → 상세 → 보드.
